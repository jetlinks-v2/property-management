# 设施设备验收

本清单用于测试环境和上线验收。当前源码已提供 PC、员工 H5、业主 H5、独立服务及配置定义；实际应用开通、设备接入、角色授权与业务验证须在目标环境执行。本轮按用户确认保留短信配置和发送记录页面，暂不接入短信服务、不验收真实受理或送达；H5 消息和员工站内信仍须通过。

## 构建及行为测试参考

以下命令供具备相应条件的开发或 CI 环境使用，不代表当前目标环境已执行或已通过。当前交付按用户要求在远程测试环境使用 10 台设备和少量用户验证；本机仅构建。

```sh
mvn -pl :property-facility-energy-service,:property-facility-energy-cloud-support,:property-facility-energy-file-support -am verify
```

后端行为测试使用 PostgreSQL Testcontainers（需要本机 Docker），覆盖并发接单、单双工单、整改后再次提交、转派后离线冲突、客户区间隔离、跨项目迁移、显式 SQL NULL、导入事务回滚、主用量指标去重、累计／增量计算、倍率、倒退恢复、计划执行单位、告警升级恢复、即将逾期、状态异常、读数异常、通知原子性、延迟余额通知复核及短信回执匹配。应用成员撤权回归验证：即使旧请求范围、租户应用资产及设备权限仍存在，非成员也不能进入设施应用或恢复后台任务／订阅。

Cloud 历史适配器测试通过真实命令工厂执行，校验固定命令 ID、设备与属性、分页、时间条件、排序、响应转换及认证上下文，权限拒绝原样传播。部署时将 core 与 cloud-support 装入 Cloud 设备进程，设施业务服务仅包含 core 与 manager；实际能源验收必须覆盖 MQTT 上报、Cloud 历史查询、标准化入库、重复采集和汇总全链路。

文件适配器使用真实 AssetsHolder 与 Spring 文件 SPI 切面验证元数据、二进制读取及压缩下载的允许／拒绝对，并检查未标记的其他应用文件不受影响。真实环境须验证专用上传后范围标记仍然存在，跨租户、应用、组织及无登录下载均拒绝；关联其他项目文件或通用未保护文件失败。照片上传成功不代表下载权限隔离已通过。

在相邻 `saas-runtime-ui` 执行：

```sh
pnpm -F jetlinks-web-core build -- --module-name facility-energy-ui
pnpm exec vue-tsc --noEmit -p modules/facility-energy-ui/tsconfig.json
```

PC 类型检查会遍历共享 Web Core。验收时需区分本模块错误与上游已有错误，不能把全量非零退出称为通过。

在 `modules/facility-energy-ui/mobile-h5` 执行：

```sh
npm ci
npm test
npm run build
```

移动端测试覆盖账号隔离、稳定提交键、附件补传失败、403／409 冲突保留、指导书缓存隔离及精确会话离线授权。浏览器模拟响应仅用于检查渲染与交互，真实后端链路须执行以下场景。

## 目标环境必须通过的场景

| 场景 | 验收要点 |
| --- | --- |
| 应用与基础 | 独立开通应用，菜单、套餐、订阅快照与角色一致；系统管理维护同一份共享档案 |
| 同步与扩展 | 重复同步仅一份台账；扩展和附件不丢失；源改名、删除、停用、恢复及分页失败符合生命周期规则 |
| 项目迁移 | 多归属确认；旧绑定关闭，映射停用；新项目看不到旧项目客户／操作历史；原项目任务和统计保留 |
| 巡检维保 | 标准、计划、重复排程、设备码和机房码；分派接单、外协／内部职责、整改、复核、归档完整跑通 |
| 离线 | 真机在线接单下载，断网执行拍照，联网补传；撤回、转派、重复提交、附件失败和撤权均显示正确结果 |
| 能源计算 | 水、电、气真实样例；累计、增量、瞬时、状态、余额；倍率、重复、乱序、换表、归零、人工更正、边界缺失和总分表不双计 |
| 预警 | 用量接近／超限、计划超标、离线、上报中断、读数异常、即将逾期；恢复、再次触发与升级通知无风暴 |
| 缴费提醒 | 只有实际且新鲜的余额触发；延迟发送前重新确认余额、规则、预警状态及收件人；用量超限不推导欠费 |
| 业主 | 多联系人中仅有查看授权者可登录；新业主不能读前业主数据；原收件人不再收到新提醒；公区通知责任员工 |
| 通知 | 本轮验收 H5 消息与员工站内信，保留短信配置和记录页面；后续启用短信时另验收真实受理、送达回执和失败重试，未知提交结果需核对供应商 |
| 报表 | 日月年、同比环比、计划执行、巡检维保完成／逾期率、故障与通知统计；缺失与不兼容单位明确标注 |
| 数据边界 | 真实 A/B 租户、应用和组织账号分别验证列表、详情、导出、附件、扫码、本人接口和后台配置人撤权 |
| 容量与恢复 | 本轮使用 10 台设备、少量用户，不执行大批量压测；保持现有内存配置，稳定性未通过如实记录。轮询上限、积压、历史补取与恢复按实际证据分别记录，不将截断当完整结果 |

撤权测试先访问业务接口以覆盖已有权限缓存，再修改组织或角色，分别记录 Cloud 授权及业务接口的生效时间。当前网关令牌转换缓存最长 60 秒（连续访问），空闲 10 秒过期。使用独立计划验证：配置人失去设备访问权后，计划到期并经过至少两个后台轮询窗口仍不生成任务、不推进排程；恢复有效授权后只生成一次。另用真实配置人创建能源映射与规则，分别移除组织及应用成员关系：撤权样本仍须到达 Cloud 原始历史，但设施标准化读数、游标、预警和通知在两个后台轮询窗口内不推进；恢复后补采一次，异常通知在指定员工 Cloud 收件箱恰好一条，其他员工不可读取，正常读数恢复预警且不重复通知。测试结束后恢复原组织、应用成员及完整角色授权，并停用专用测试配置。

角色数据范围测试须显式收窄有效策略，并检查账号所有角色。仅删除 `assetAccesses` 可能触发菜单默认策略，不能据此认定已失去设备权限。可将设施及 Cloud 设备范围收窄为 `creator`，选用非该账号创建的设备；确认业务详情返回 403、组织及应用成员身份仍有效后，再开始撤权期间的后台轮询观测。

服务重启补偿应使用专用仪表和禁用短信的规则：先建立正常基线，仅停止设施服务，保持 Cloud 接收真实上报；重新启动后逐条核对标准化记录、计量结果和原生通知收件箱。再提交完全相同的时间戳及消息标识，确认不重复计量；通知已发送后再次重启并观察至少两个轮询窗口，确认不重复投递。并发冒烟须记录实际并发数、请求总数、失败数及延迟，不能代替目标规模的容量验收。结束后读回确认原始配置已恢复。

数据库恢复测试应从一致性快照生成逻辑备份，恢复到独立临时库，核对所有业务表的行数、结构与约束。设施库恢复通过后，仍需单独验证 Cloud、基础档案和文件存储联合恢复及恢复后的实际业务访问。

首版从建立有效计量基线后开始统计。旧历史迁移、仓库耗材、费用账单与支付、远程断供、微信及报事报修自动联动另行安排。
