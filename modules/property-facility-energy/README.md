# 设施设备能源管理

## 整项接单与逐设备执行

同一任务配置同一执行时隙生成一项任务及去重后的设备明细。整项任务统一接单、派单、转单、关闭和审批；设备明细分别保存检查要求快照、结果、照片、版本和提交幂等键。所有设备提交后，整项任务进入待审批；驳回后原接单人逐设备整改，转单清空原检查结果。旧工单不自动重组。任务列表和统计仅计整项任务及旧工单，设备明细不重复计数。

H5 任务详情显示设备清单及已提交数，扫码携带当前任务上下文：设备组码只显示该任务快照中组内设备，设备码打开该任务对应设备，拒绝其他任务、项目或应用二维码。独立扫码仍可选择该设备的相关任务。权限继续使用 facilityTask 的 AssetsHolder、租户/应用边界、项目成员关系；不新增角色授权。设备清单读取先校验父任务，再对明细查询注入资产范围；动作及级联在同一事务内使用版本校验，故障仍关联到具体设备。

周期计划新增用户填写的预警时间，按单次任务开始后经过的时间计算，至少为单次执行时长的一半且早于结束时间；生成任务时保存预警时间快照。独立轮询向有实时应用、项目及任务资产权限的人员生成新任务、预警和超期站内消息；已接单任务提醒接单人，预警和超期同时提醒负责人，审批及终态停止提醒。同一整项任务、消息类型及接收人只生成一次；个人收件箱的分页、未读及已读操作按账号和任务资产权限隔离，不改变任务版本。

独立 Cloud 应用，业务由 property-facility-energy-manager 承载，property-facility-energy-service 装配。默认端口8508/18508/28508，库property_facility_energy，接口/property/facility-energy。共享基础数据仅通过property-base-core公开命令访问。

业务设计：[设施设备能源管理系统设计](../../../设计文档/设施设备能源管理系统设计.md)。PC与移动端位于独立facility-energy-ui；部署菜单、应用模板及环境示例位于deploy/facility-energy。

构建：`mvn -pl :property-facility-energy-service -am verify`。不要将base-manager、repair-manager、quality-manager或patrol-manager加入本服务。上线须独立验收SaaS应用、角色资产范围、Cloud设备、短信通知器及回执，不以打包成功代替联调。

设备巡检、维保使用同一个业务开关，沿用原有 `inspectionEnabled`、`maintenanceEnabled` 列，任一为真即视为已启用；设备资料保存时同步两列。设备组保存只接受同项目且已启用巡检维保的设备，任务配置及生成使用相同启用判断，停用后阻止后续生成，不删除已有工单。

### 组织权限查询

设备档案负责人通过 `GET /property/facility-energy/context/employees/{projectId}` 查询：先确认项目在当前授权目录内，再通过基础员工分页命令按项目组织的直接成员关系筛选有效员工。保留调用者的用户资产权限，不扩大到上级、兄弟或下级组织；未归属项目的设备不加载全量负责人。每批最多200人，连续读取后续页。

设施资产沿用 `AssetsHolder` 的 `org-include-children` 策略。认证服务已经展开有权访问的下级组织；设施服务通过 `FacilityOrganizationAccessSupport` 将这些维度交给标准维度条件构建器，不使用本地 `s_dimension_closure` 优化。组织层级由共享档案和 Cloud 持有，设施库不复制该表数据。这个扩展只改变设施资产的查询生成方式，保留既有组织、创建人、租户及应用权限。其他资产继续使用框架原策略。

`GET /property/facility-energy/context/organizations` 返回外协组织树，只保留调用者有权查看且标注为 `external` 的单位及其上级路径；上级仅用于展示，只有外协单位可选。该组织目录保留用于基础资料查询；任务不再使用外协单位或区分单、双工单。

作业标准只维护作业类型与检查要求。巡检／维保的“周期计划”绑定项目，配置星期、多时段、频率、次数、最小间隔和指定日期覆盖；不在周期计划中填写有效期。巡检／维保各自子菜单中的“任务配置”选择同项目、同作业类型的周期计划、作业标准、负责人、机房／设备组，并设置开始／结束有效期和启停。机房／设备组至少选一个，组内必须有可用设备；服务端展开并去重，最多1000台。负责人限定项目所属组织的有效员工，所有工单进入项目工单池，仅项目所属组织的有效员工可接单或被派单，提交后直接由负责人审核。任务仅由后台按周期自动生成；单次执行在周期计划高级配置中指定日期和时段，不开放手动生成接口或临时任务入口。

时段按业务时区Asia/Shanghai计算，跨天归开始日期，日期覆盖优先；相同起止代表24小时。完整频率周期内按次数均分独立任务窗口，剩余尾段不补次数，最小间隔排不下时拒绝保存。例如08:00–12:00每小时1次，生成4项任务，每项包含该配置下全部去重设备明细。有效期内只生成起点不早于开始时间的任务，截止时间不超过配置结束时间；最长有效期10年。每配置日最多10000次，每次轮询按一个时隙最多1000台写入，后续时隙使用持久化游标推进，不一次展开整年工单。

`fe_cycle` / `facilityCycle` 及 `facility-cycle:query/save/delete` 为周期计划独立记录和权限；`fe_plan.cycleId` 引用周期计划，其有效期保留在任务配置。引用中的周期计划禁止删除，停用停止后续生成；修改规则唤醒关联配置重新计算未来时隙，不覆盖已生成任务。生成、游标推进和引用锁同事务，稳定任务ID防止重复；失败回滚且通过原Jobs日志/MBean报告。升级时保留旧计划及工单数据；未绑定周期计划的旧配置需显式补齐，不再按旧间隔偷偷继续生成。该策略不自动迁移月／年间隔。新表及字段由服务现有EasyORM实体初始化同步；部署后需增量同步本模块菜单、模板与角色权限，不自动扩大现有账号授权。

任务列表展示项目、任务开始／结束时间（精确到分钟），操作列提供派单、转单和关闭。审批弹窗按当前负责人及任务资产权限筛选，提供待审批、已通过、已驳回、全部页签；已驳回对应当前待整改任务，重新提交后回到待审批。待审批支持逐条与批量通过／驳回，每条独立校验版本和权限并反馈结果。驳回保留原接单人继续整改；转单清空原执行结果，关闭后不可继续执行或审批，关闭任务不计入超时与完成率分母。候选人员查询保留任务 save 资产权限与基础人员目录权限；H5 工单池先按本人组织过滤后分页，领取、转派、开始、提交及离线重放实时复核项目成员关系。旧双工单不再进入内部跟进，已提交的旧外协任务可直接审核；原存储字段仅兼容历史，保存配置时清空且不再对外返回。

## 设备归属与水电计费配置

配置管理包含设备归属配置、水电计费配置两个页面。设备归属按授权范围分页查询；可批量配置业务项目和普通设备／水表／电表分类，单设备选择安装空间。同步保留人工确认的业务归属。换项目关闭原绑定、停用计量映射并迁移设备组织资产权限；项目、空间或分类变化重新记录归属生效时间，不用当前归属追溯旧月份。批次至多200台，同批版本冲突整体回滚。

水电计费按项目和能源类型配置收费科目、标准、公式用量变量及其他必要固定变量。标准候选只来自收费服务已下发科目，金额由收费服务现有公式执行器计算；单价、面积和月数由服务端提供。计费规则变更保留有效期版本，启停不重写历史日期，一个自然月必须由同一规则和标准完整覆盖。

账单采用自然月预览、确认后生成应收。户表须启用能源计量，项目／分类／安装空间须有覆盖整月的归属证据，认可读数必须完整且无异常，安装空间只有一个覆盖整月的有效客户。月中换客户、空间或标准不能直接整月计费；总表、公共表不自动摊给住户。既有设备缺少历史归属证据的月份明确阻止出账，不自动补造历史。

设施与收费服务仅互依公开core契约：`facilityService:meter-usage`提供受当前设备资产权限约束的身份及用量证据，`financeService:meter-billing`提供收费标准候选、预览和确认。参数存于平台命令容器，保留调用者认证、租户与资产范围。确认只接收设备、账期、日期和预览指纹，服务端重新读取来源，财务期间锁与稳定设备月度键保证并发／重试不重复。正式应收冻结来源快照、生成YS单号，进入待审核和未收款状态；规则停用不影响已落账事实查询。批量每次最多100条，逐条事务并明确返回成功单号或失败原因。

新增菜单和按钮在`baseMenu.json`交付，由管理员初始化及授权；不会自动扩大现有角色权限。设施、收费仍独立打包运行，两个service的JAR只包含自身manager。
