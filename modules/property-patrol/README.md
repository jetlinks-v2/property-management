# 智能巡更后端

本仓库是巡更后端的唯一开发入口。巡更是独立的 JetLinks SaaS 业务服务，装配自己的 manager/core，并通过 property-base-core 公开只读命令读取组织和有效员工，不装配 base-manager、不调用财务业务，不在门禁服务内实现巡更，不复制 SaaS 的登录、用户、组织或授权角色。面向 PC 管理端和后续执行端，业务时间统一为 `Asia/Shanghai`。

本人巡更资格校验 SaaS 已认证身份中的当前业务应用成员维度，入口 Scope 不是成员凭据；配置其他人员使用有效员工、SaaS当前应用成员及 user 资产范围的交集。普通巡更人员无需因此取得系统用户查询权限。任务执行仍受计划资产、业务角色和排班约束。无真实时段的生成封印保留防重，但不进入 PC 任务组列表、计数、详情或导出。

## 模块与能力入口

| 模块 | 职责 |
| --- | --- |
| `property-patrol-core` | 无 I/O 的规则展开、跨天冲突检查、执行资格策略 |
| `property-patrol-manager` | 配置资产、计划、应用角色引用、排班、任务与执行事务、检查判定、受控附件、人员 SDK 适配、查询与统计 |
| `services/property-patrol-service` | SaaS 微服务启动、认证与发现、PostgreSQL/R2DBC、Redis |

PC 模块位于 SaaS 的 `runtime-ui/modules/cloud-patrol-ui`，前端仍独立维护。配置包括分类、点位、检查标准、应用角色指派、人员排班和巡更计划；PC 沿原菜单组织，单点/批量角色及规则指派、月模板下载与导入统一从点位管理进入；角色及成员在当前应用角色管理中维护；内部计划和时段任务不设独立菜单。记录按任务组分页，详情查看真实时段，统计统一为巡更履行总览，原统计接口继续兼容。在线执行接口由 H5 消费，PC 不冒充移动打卡终端。

**这不是旧系统全量迁移版本。** 点位批量导入导出、PC二维码图片和打印已有；不包含小程序页面、扫码真机与APP硬件识别验收、集团模板、离线包/补传、外部流程审批、预警通知、人员评价、集团综合报表、旧API兼容及历史数据迁移。PC/H5 NFC与定位暂缓。数据库测试与独立打包也不代表已经通过真实SaaS联调或生产验收。

## 数据与业务契约

- 各类配置是独立资产，使用 `AssetsHolder` 维护项目与应用范围。任务、执行记录和统计关联 `patrolPlan`，不能通过自传项目 ID 扩大查询范围。
- 点位编码选填：手工填写时去除首尾空格；新增留空按既有导入规则生成 `PT` 加点位ID（去连字符、转大写），应用内唯一索引仍兜底防重。编辑留空保留原编码；二维码仍按点位ID识别。导入使用同一生成规则。
- 新增 ID、归属和审计由服务端维护；创建/修改姓名快照取自可信SaaS身份，覆盖配置入口、导入和角色规则操作，编辑保留原创建人。历史缺失不按当前人员姓名回填，客户端不能改写姓名快照。新增配置与资产绑定在同一事务；编辑不能移动归属。配置不开放物理删除；分类、等级、标准、预警另有逻辑删除，停用不是删除。删除项从列表/分页/详情/候选/导出排除，底层及历史快照保留；引用中的等级/标准（含停用角色关系）不可删除，引用和删除共用行锁。分类只删除当前节点：存在未删除下级、点位关系（含停用关系）或巡更规则时拒绝，不级联删除；分类树节点悬停显示新增下级和删除图标，新增下级继承父分类项目并锁定。
- `scopeKey` 使用当前业务应用 ID，`projectId` 标识业务项目，技术租户不参与巡更业务分组；这些字段不是数据权限过滤的替代物。点位编码在应用范围内唯一。分类不能循环，计划的点位和标准必须同项目且可用，角色必须来自同一应用。
- 巡更直接引用当前应用的授权角色及成员关系，不另建业务角色；具有角色并不自动获得任意点位执行资格，仍须满足指派和排班等业务约束。人员使用基础服务中的有效员工，并与启用账号、当前应用成员及 `user` 资产权限相交，不以技术租户代替业务项目。
- 巡更配置同页展示角色及其等级/标准，打开仅查询即可查看已有配置。统一使用一个保存动作，在同一事务内提交角色及规则，无需先指派角色。等级和标准均为空时只保存角色且暂不生成任务，只填一项拒绝保存；已有配置两项都清空时清除后续生成规则，历史任务快照保留；批量联合保存统一所选点位，显示第一个点位作为编辑基准。
- `pt_plan` 承载点位及分类下的角色或全员规则，空 `roleId` 表示全员任务，不映射虚拟应用角色；角色和全员可分别配置，彼此独立计次。可暂不配置标准与规则；未配置不生成任务。规则配置只选择等级与标准，不要求人工名称、生效期限或排班策略；新配置按星期和高级日期决定巡更日期，历史期限在仅调整角色时保留，重新配置规则时取消人工期限。**同角色的任务完成次数共享，不按角色内每个人各生成一份任务**；不同角色使用独立计划。
- 指定角色保留仍选角色的规则，移除只停用关系，重新选择复用计划ID及全部历史。批量规则要求所有点位角色相同，按第一点位配置覆盖。每次最多100点位、20角色；点位与已有计划分别校验资产read/save，引用read由统一校验器负责；事务内CAS点位版本、批量保存和绑定，失败整体回滚。
- 日期覆盖优先于星期规则，空覆盖表示当日休巡。时段左闭右开，结束分钟小于开始分钟表示跨天，开始等于结束表示从开始起24小时，结束 `1440` 表示当日24点。每个配置时段保留一条任务和完整起止，应巡次数为 `floor(时段分钟数/频率分钟数) × times`，不足一周期仍保留应巡0次的时段；每时段独立配置冷却，录入单位支持分钟/小时/天。跨天任务归开始的逻辑日期。
- 排班也归班次开始日，单班不超过24小时。指定角色任务按项目及任务开始日判断：没有排班时角色成员可执行；存在排班时还必须命中本人当前非休息班次，不要求班次角色与任务角色相同。全员任务不限制角色和排班，但仍校验有效员工、应用成员、项目/计划资产、时段、次数及间隔。已持久化的 `rosterPolicy` 字段保留，`required` 不再强制创建排班。
- 任务每天上海时间 00:01 自动生成，按持久化计划归属恢复租户，角色名称使用保存指派时由当前应用目录验证的只读快照；后台不冒充用户查询角色或成员。HTTP 手动生成仍要求计划资产 save，并查询当前应用有效角色。角色停用或移除后，本人执行资格实时拒绝，不因已有任务快照放行。多节点使用同一数据库封印防重，失败按计划记录日志。
- 月排班使用人员 ID，角色 ID 可留空；模板包含当前项目有权使用的有效员工，不以是否加入角色排除员工。前四行表头、第五行示例、第六行起填写；班次表明确起止时间，结束小于开始表示跨天，休息不计在班。最多1000行、5MB、100个班次，不直接接受旧手机号模板。整月替换先验证有效员工（选择角色时另核实角色成员）和既有排班资产 save，再在事务内停用旧排班、插入和绑定新排班；失败整批回滚，并发版本防止交错覆盖。
- 日历按任务规则归属日 `belongDate` 展示；已部署旧任务缺少该字段时使用其 `businessDate`。顶部仅展示所选月的已排班天数、去重排班人数；日期格仅显示已完成点位数/应巡点位数，不跨天累计“点位天”。日详情展示应巡、已完成、漏检、缺勤点位数，按项目和点位去重，多个角色/时段不重复计点位。同一点位所有角色、全部时段均达到要求才计已完成；至少有一次有效巡更且存在逾期未完成要求的点位计漏检；所有应巡时段均已结束且一次有效巡更也没有的点位计缺勤，漏检与缺勤互斥，未开始或仍可执行的未巡点位不提前判缺勤。日详情区分未巡、未开始、部分完成、已完成，漏检/缺勤独立标记；月汇总及日期格子分别展示漏检、缺勤点位；月数量为每日点位数累加，同一点位跨日分别计数。次数与时段在展开后的执行明细及导出中展示，导出另含点位日统计。任务分类沿生成时的名称快照展示及导出，不回查当前分类名称。日详情及导出的手机号仅对具有 `user:query` 且能读取对应用户资产的操作者补充，并限定当前应用成员；无权限或未录号码时留空，不扩大巡更人员权限，不把联系方式保存到排班历史。
- 首次生成某计划某日的封印及全部任务在同一事务内写入；即使该日无任务，也保留封印。并发依靠数据库唯一键防重，规则/标准编辑不会覆盖该日任务快照，也不会因为规则版本变化重复应巡。
- 漏检申报资格与在线执行分开：全员任务可申报；指定任务允许匹配角色，或者本人在任务结束日有与该时段重叠的非休息班次，班次同样限定当前应用及项目。申报不授予正常打卡资格，也不绕过资产授权。

- 任务保存点位/角色名称、分类ID与名称、等级ID与名称、时窗、次数、冷却、排班策略、检查项等快照。执行资格复核当前计划/点位/角色启用状态、实时角色成员、当前账号/应用成员和排班。历史记录按快照解释。
- `pt_execution.collectedTime`和`networkStatus`保存客户端首次提交时的采集时间（毫秒）及连接状态（`online/offline`），允许已发布客户端省略，历史缺失不按接收时间回填。这些信息只用于追溯，在线资格、冷却与计次仍由服务器时间决定；不构成离线补传接口。
- 提交使用服务端当前用户；`requestId` 在同一执行用户下必须唯一。同请求重放不重复计数，不同内容（含采集时间/网络状态）复用同编号拒绝。任务计数 CAS 和执行记录原子提交，失败整体回滚。
- 检查项内容最多200字，支持 `number/text/choice/image`，缺少类型的已部署标准按 `choice` 读取。沿原通邑口径，检查结果展示实际答案：数值在包含边界的上下限之外标为异常；选项首项为正常答案，其余答案为异常。文本、图像、未配置数值范围及选填空项只展示内容，不自动判断异常。数值上下限最多18位整数和6位小数，通过 JSON 字符串传输防止精度丢失。异常不阻止有效执行计数。
- PC、H5和记录导出均使用执行时的标准与答案快照标识异常，不套用当前标准，不显示整体或逐题“未判定”。已部署的 `qualifiedOptions` 字段保留以兼容请求与快照，但不再决定选项是否正常；编辑标准时按首项收敛。内部 `result/itemResults` 字段继续供异常统计使用：任一异常为 `fail`，否则存在已判断正常项为 `pass`，其余为 `not_evaluated`；它不是整次巡更的质量合格结论，也不影响次数完成统计。历史持久化标记不批量覆盖。
- 图片每题最多一张，例图与执行图片用途隔离。上传只接受 JPEG/PNG/WebP 文件头，最大5MB；拒绝 SVG 和任意外部 URL。复用平台 `fileService` 命令，巡更只登记受控附件 ID。引用须通过资产 read、同项目/应用和用途校验；执行图片另校验上传者。预览在认证请求内返回限长 data URL，不向前端泄露平台内部地址。
- 文件写入平台后，本地附件登记和资产绑定在同一事务；绑定失败则登记回滚。远端文件无法随业务事务回滚，可能留下未引用文件；平台可能复用文件 ID，因此不在失败补偿中盲目删除。生产上线前需明确平台保留与清理策略。当前文件头检查不等于完整图片解码验证，普通图片上传也不能证明现场拍摄；原生相机及采集证据待 APP 对接。
- JSON 列通过 EasyORM 公开元数据扩展复用 Spring 的标准 `ObjectMapper`，与 HTTP 的日期键和 record 契约一致。

- PC 日任务组按首时段的分类/等级生成快照筛选，先分页再批量读取本页时段汇总进度；历史没有分类名称快照时留空，不以当前配置冒充历史。执行记录通过真实 taskId 展示原时段起止、分类和等级，不改变打卡事实。
- 三类统计的周期、分组行、全范围总计和XLSX导出共用资产授权查询；总计点位去重，覆盖率按总有效次数/总应巡次数计算，不平均分组百分比。未完成次数包含未截止任务，不一律标成漏检。人员页保留角色口径，不将整个角色的次数复制给各成员。
- PC/H5 的 NFC、定位、点位坐标与打卡范围整链暂缓；不因此暂缓图片、二维码、记录或本系统漏检业务。

等级修改记录只从启用此能力后的真实操作追加，保存可信操作人姓名和名称/状态/说明/规则前后快照，写入与配置同一事务；不回填虚构历史。标准与标签不额外开放该历史入口。配置导出规则/检查项使用独立明细表及流式写入，不扩展未经授权的图片、人员或集团信息。等级、标准、分类的删除按钮在模板中作为可分配权限开放，角色和人员是否可删除仍通过权限管理决定，不自动授予现有角色。既有环境需先增量开放应用模板对应按钮，再按职责配置角色权限。分类新增及移动连同子树限制为三级；历史深层分类原父级不变时允许编辑资料，不自动迁移。

## 巡更记录导出

记录页的导出沿用当前筛选；有勾选时取勾选ID与筛选、应用及项目资产权限的交集。一个XLSX包含三张表：

- 点位巡更记录：所属项目第一列，应巡次数后展示任务状态；以稳定的“日任务编号”关联执行记录。同一点位不同角色分别保留日任务，不再展示计划/点位技术编号、规则版本、时段数或起止时间。
- 执行记录：每次打卡独立一行，同一日任务的项目、点位、分类、等级、日期、角色及日任务编号纵向合并；归属日期后展示完整起止日期时间组成的巡更时段。巡更时间使用服务器接收时间，不同时导出设备采集时间；执行编号关联检查项结果。
- 检查项结果：使用执行时的标准和答案快照，展示检查项名称、类型、结果及适用的数值上下限/选项，不使用当前配置回填历史缺失值。现场图片、例图作为保持比例的缩略图嵌入单元格，不导出附件编号或带凭据外链；支持JPEG/PNG/WebP，无权、失效或不支持解码的图片注明原因。

不导出独立的巡更时段表，不关联漏检申报或审核历史。有效完成次数仍沿用业务计数（可能含审核补计），不将其伪装成真实执行条数。任务状态为已完成、漏检、缺勤、进行中或未开始：全部应巡完成即已完成；整组全部时段结束后，部分完成为漏检，一次未巡为缺勤，与记录页固定颜色口径一致。

页面创建后台导出任务，短请求查询进度，完成后自动下载；导出期间提示不要刷新或关闭页面，请求不使用客户端15秒超时。创建、进度及下载均校验当前用户、应用和所选项目；生成时过滤计划资产，图片额外要求附件query及自身资产read，下载前重新校验源计划和已嵌入图片权限。图片无权不阻断其他有权记录的导出，其他存储故障明确失败。

任务组上限10000条，查询的时段、执行和检查项合计预算100000条，图片最多4000个唯一附件且缩略图合计不超过64MB；超限整次失败并提示分批，不静默截断。每64组批量读取关联事实，流式写表并清理POI临时文件；POI压缩、图片解码及文件I/O在阻塞调度器执行，不改变日常分页查询。数据来自生成期间多次受控查询，不承诺跨查询数据库事务快照。

后台任务适用于当前单实例部署：最多2个同时生成、保留8份任务，生成最长45分钟，完成文件保留1小时，定时及服务关闭清理。重启将丢弃任务；扩为多实例时须使用共享任务存储/文件存储或固定实例路由。运行上下文只在任务执行期间传递，不将凭据写入任务元数据或文件；JMX `org.jetlinks:type=PatrolRecordExports` 提供运行/保留数量，不暴露文件位置和用户信息。原同步导出端点保留兼容，页面改用后台任务。

默认点位查询、分页、计数和导出排除全部分类关系已取消的点位；没有关系记录的历史点位保留原分类回退。取消不删除物理点位、历史计划或执行事实。

## 点位分类关系

一个物理点位可关联多个分类，角色和规则按“点位＋分类＋角色”独立配置。`pt_point_category` 保存当前关系及取消后的停用行；`pt_point.categoryId` 保留初始分类，仅在尚无关系行时兼容历史数据。首次调整分类时在点位锁内迁移旧关系和计划分类，保留原计划ID；`categoryIds` 为服务端只读投影，不接受客户端覆盖。

`POST /park/patrol/point-categories/link`、`/cancel` 接收 `{pointIds:[...],categoryId}`，最多100点位。操作使用点位save、引用分类read及受影响计划save权限，当前应用校验和整批事务同时生效。取消仅停用所选分类下的计划，保留物理点位、任务封印、执行及漏检历史；重新关联不自动启用旧计划。角色编辑与分类取消通过点位锁及版本比较防止交错覆盖。

分类侧栏、角色规则编辑、任务生成和点位导出使用当前关系。多分类点位配置角色时必须选择分类；全部分类概览汇总可读的有效计划。按分类导出只显示该分类及其角色，概览导出全部当前分类；全部取消后保留物理点位供重新关联，不以初始分类回填。

## 人员与业务边界

巡更人员取物业基础数据中的有效员工，并与 SaaS 当前应用成员和 user 资产范围相交。应用成员关系在认证服务解析，员工身份及直接组织在基础服务查询；不复制主数据。纯客户/业主不作为执行人员，双身份按 employee 状态判断。巡更角色来自当前应用实例，不使用平台角色或其他应用角色。SaaS 技术租户不等于园区业务项目：平台创建的应用允许没有租户，内部范围键保留可空租户部分与应用 ID；应用 Scope 始终必需。有租户的定时计划恢复原上下文，无租户应用不伪造租户。

## 业务项目与执行边界

- `GET /park/patrol/projects/_tree` 读取基础服务已过滤的组织树，不重算组织及下级权限、不补查不可见祖先。非 project 节点保留层级，置灰禁选；无项目不是全库权限。
- 可选 `X-Patrol-Project` 只能选择树内 project，收窄当前请求；省略表示全部有权项目。它不替代应用 Scope、功能或资产权限，应用ID、宿主项目编码、租户ID都不等于业务项目ID。
- 等级、标准、分类、标签、图片、点位、计划、排班及执行事实归项目；计划从点位继承项目，排班需明确所属项目，项目内配置引用不能跨项目。应用角色在应用内共享，异常预警为当前系统应用的全局配置，二者不归属业务项目。普通编辑不能变更项目归属，不支持组织共享项目配置。
- 现有资产授权与项目范围相交，在分页、汇总前过滤；新配置沿用平台自动应用资产绑定，组织范围直接由已授权基础树与业务归属相交，不新增组织资产授权。管理范围不授予执行资格：始终要求有效员工、当前应用成员、项目及资产权限、时窗、次数和间隔；角色与排班条件按上述指定/全员任务区分。普通执行人员无需员工目录维护权限。
- 任务组、时段和执行记录保存项目快照，不改变任务组ID、日期、时段或计次。已有未归属项目数据（包括旧版组织归属配置）不随机分配；在项目工具条“历史数据归属”中审查后处理，通常先分类/标准/等级，再点位，最后计划/排班。自动生成跳过无项目旧计划。
- `POST /park/patrol/project-migrations/_query` 输入 `{type,query}`，只查当前应用、原资产授权下未归属配置；`POST .../assign` 输入 `{type,ids,projectId}`，每次1–100条，要求对应 query/save 功能权限、原资产save和目标项目可见。只允许 projectId 为空的数据归属到明确项目，清空旧 ownerOrganizationId，CAS更新与事务保护；计划历史只补缺失项目字段，不改计数与打卡事实。
- 标准例图和执行证据都必须属于项目，使用 `X-Patrol-Project`，不再处理 `X-Patrol-Owner`。`ownerOrganizationId` 只保留作旧数据迁移字段，不参与授权或业务引用。

项目名称保留生成时快照。项目标注撤销、组织停用或权限撤回后，下次请求不再访问其数据；恢复授权后可重新访问。基础组织生命周期目前不反查巡更引用，后续如需删除阻断应通过公开契约协调，不能跨表耦合。

## API

统一使用宿主认证、响应包装及 QueryParam/PagerResult，不另建旧式返回包装。下表是服务内部路径；经过网关时的外部前缀由平台部署决定。

| 操作 | 路径 | 功能权限 |
| --- | --- | --- |
| 配置分页/详情 | `POST /park/patrol/{resource}/_query`、`GET /park/patrol/{resource}/{id}` | 对应 `patrol-category/point/standard/roster/plan:query` |
| 新增/完整编辑配置 | `POST /park/patrol/{resource}`、`PUT /park/patrol/{resource}/{id}` | 对应 `:save`，编辑另校验资产 save |
| 等级修改记录 | `POST /park/patrol/levels/{id}/history/_query` | `patrol-level:query` + 等级资产read + 当前应用，最大50条/页 |
| 配置XLSX导出 | `POST /park/patrol/{levels\|standards\|tags}/_export` | 对应query + 当前应用及资产read；10000配置/100000明细上限 |
| 配置逻辑删除 | `DELETE /park/patrol/{categories\|levels\|standards\|warnings}/{id}` | 对应delete + 配置资产delete + 当前应用，不级联历史 |
| 点位角色回填 | `POST /park/patrol/point-assignments/_detail`，`{pointIds:[...],categoryId}`；概览使用 `/_summary` | `patrol-plan:query` + 点位及有效计划资产read |
| 点位导入模板 | `GET /park/patrol/points/workbook/template` | `patrol-point:query`，必须选择所属项目，仅含当前应用/项目可读且启用的分类，参考表提供分类路径与所属项目 |
| 点位导入预检/提交 | `POST /park/patrol/points/workbook/preview`、`/import`，multipart字段`file` | `patrol-point:save`；必须选择所属项目，重新检查分类read/当前应用、启用状态、名称及项目一致性；同分类+名称+位置的文件内或当前项目可见库内重复均拒绝；任一行错误整批不写入，新增资产绑定与插入同一事务 |
| 点位导出 | `POST /park/patrol/points/workbook/export?categoryId=...`，QueryParam；分类参数可省略 | `patrol-point:query` + 点位资产read；名称引用独立read；全筛选最多10000点位 |
| 批量指定角色 | `POST /park/patrol/point-assignments/roles`，`{pointIds:[...],categoryId,roleIds:[...]}` | `patrol-plan:save` + 点位及已有计划资产save |
| 批量配置规则 | `POST /park/patrol/point-assignments/rules`，`{pointIds:[...],categoryId,rules:[{roleId,levelId,standardId}]}` | `patrol-plan:save` + 点位及已有计划资产save |
| 角色及规则联合保存 | `POST /park/patrol/point-assignments/configuration`，`{pointIds:[...],categoryId,rules:[{roleId,levelId,standardId}]}`；无需预先指派；等级与标准可同时为空，填写时须成对，失败整体回滚，保留指派ID与任务历史 | `patrol-plan:save` + 点位及已有计划资产save，沿用关联引用校验 |
| 当前应用角色分页 | `POST /park/patrol/roles/_query` | 当前应用 Scope + role/user 资产read，只读 |
| 可用人员分页 | `POST /park/patrol/persons/_query` | `patrol-point:query` |
| 任务分页/详情 | `/park/patrol/tasks/**` 只读查询 | `patrol-task:query` + 计划资产 read |
| 任务预览 | `POST /park/patrol/tasks/_preview` | `patrol-task:query` + 计划资产 read |
| 月排班模板/导入 | `GET /park/patrol/rosters/month/template?month=YYYY-MM`、`POST /park/patrol/rosters/month/import?month=YYYY-MM`，multipart 字段 `file` | `patrol-roster:query/save`；导入另校验既有排班资产 save |
| 手动生成 | `POST /park/patrol/tasks/_generate`，`{date:"YYYY-MM-DD",planId?:"..."}`；省略planId按当前应用、有权项目及计划save权限批量生成，跳过停用、未配规则或不在有效期的计划；重复调用复用已生成任务 | `patrol-task:generate` + 计划资产 save |
| 图片上传 | `POST /park/patrol/attachments/{example\|evidence}`，multipart 字段 `file` | `patrol-attachment:save` + 可信项目/应用上下文，成功后绑定附件资产 |
| 图片预览 | `GET /park/patrol/attachments/{id}/preview` | `patrol-attachment:query` + 附件资产 read |
| 执行结果提交 | `POST /park/patrol/executions` | `patrol-execution:submit` + 计划资产 read + 业务资格 |
| 执行记录分页/详情 | `/park/patrol/executions/**` 只读查询 | `patrol-execution:query` + 计划资产 read |
| 巡更记录后台导出 | `POST /park/patrol/task-groups/export-jobs`（QueryParam），`GET /export-jobs/{id}` 进度，`GET /export-jobs/{id}/file` 下载；后两者共用 `/park/patrol/task-groups` 前缀 | `patrol-execution:query` + 计划资产read及项目范围；10000任务组、100000展开明细上限 |
| 完成统计 | `POST /park/patrol/reports/summary` | `patrol-report:query` + 计划资产范围 |

`resource` 为 `categories`、`points`、`standards`、`posts`、`rosters`、`plans`。预览/生成请求为 `{ "planId": "…", "date": "YYYY-MM-DD" }`。提交请求为 `{ "taskId": "…", "requestId": "…", "answers": [{"itemId":"…","value":"…","attachmentId":"…"}], "remark": "…", "collectedTime": 1793751000000, "networkStatus": "online" }`，采集字段可省略，图像题不填 `value`，通过 `attachmentId` 引用本人上传的 `evidence` 图片；例图通过检查项 `exampleFileId` 引用 `example` 图片。不可用例图替代执行证据。不接受客户端执行用户或采集时间来绕过资格。

统计接收 `{ "from": "YYYY-MM-DD", "to": "YYYY-MM-DD" }`，含首尾最多31天。`expected` 为应巡次数之和，`completed` 为已接受执行次数之和，`completeWindows` 为达标时段数，`overdueMissing` 为已结束时段未完成次数。完成率不等于检查合格率，申请/审批豁免不混入正常执行事实。尚未生成的任务不在统计分母中。

排班月历仅查询进度统计和班次所需字段，不加载任务检查标准快照或进行任务明细排序；日详情及导出仍返回完整快照和稳定顺序。排班与任务分别注入原有排班资产、计划资产权限，查询在数据库限制为50001条，超过50000条明确报错；月份聚合按规则归属日分组，旧任务回退businessDate。点位完成仍要求全部角色及时段达标，漏检与缺勤口径不变。

## SaaS 接入与运行配置

使用 `deploy/patrol/patrol.env.example` 准备环境变量，不包含真实密码。数据库默认名为 `cloud_patrol`，建议分配独立业务库和账号，避免误用平台测试库；由部署方先创建数据库。持久化表由平台 EasyORM 初始化机制管理。HTTP 默认8502、集群18502、RPC28502，端口均可覆盖；多实例必须配置不同 `SERVER_ID`。

```bash
# 仅在接入环境准备完毕后执行，不属于平台部署脚本。
set -a
source /absolute/path/to/patrol.env
set +a
java \
  --add-opens=java.base/java.lang=ALL-UNNAMED \
  --add-opens=java.base/java.util=ALL-UNNAMED \
  --add-opens=java.base/java.time=ALL-UNNAMED \
  --add-opens=java.base/java.util.concurrent=ALL-UNNAMED \
  --add-opens=java.base/java.io=ALL-UNNAMED \
  --add-opens=java.base/java.net=ALL-UNNAMED \
  --add-opens=java.base/java.text=ALL-UNNAMED \
  --add-opens=java.base/java.math=ALL-UNNAMED \
  --add-opens=java.scripting/javax.script=ALL-UNNAMED \
  -jar services/property-patrol-service/target/application.jar
```

JDK17/21 下沿用平台启动脚本的模块开放参数，供现有 Redis/FST 序列化组件使用。缺少这些参数可能在集群节点写入 Redis 时触发 `InaccessibleObjectException`；不要通过关闭集群或替换公共序列化格式绕过。

必须和平台对齐集群种子、RPC token、JWT 公钥、网络可达的广播地址及 Redis 配置。业务库保持独立；不要复制参考项目里的默认密码，也不要为巡更另起一个认证系统。

应用装配顺序：

1. 启动巡更服务并确认发现与网关路由能够到达 `/park/patrol/**`。服务名为 `cloud-patrol-service`；反向代理/外部前缀需由部署方与 PC 的宿主请求路径对齐。
2. 将 PC 模块接入 runtime-ui，**增量**导入巡更菜单，不全量覆盖其他应用菜单。
3. 将 `deploy/patrol/authentication-patrol-application.yml` 作为认证服务的外部配置加载，不能加载到巡更服务代替认证装配。模板初始化关联已有菜单；已存在同 code 的模板不会靠重启自动覆写。
4. 在项目中创建启用 `CloudPatrol` 应用，分配成员、菜单/按钮权限并关联获准使用的用户资产。新建巡更配置资产为 `SELECT_AND_BIND`，平台用户为 `SELECT`。既有资产需要显式关联应用。
5. 从项目的**应用入口**进入。项目上下文、`X-Asset-Scope` 与认证由宿主携带，不手工加旁路 token。用两个项目、同项目不同应用、只读与维护角色分别验收。

本批新增 `patrolAttachment` 资产和 `patrol-attachment:query/save` 权限。已有环境需要增量更新标准/任务/记录菜单、标准保存按钮和 CloudPatrol 模板资产范围，并刷新订阅及应用授权；只重启巡更不会自动更新持久化菜单/模板。前后端制品需要一起更新，附件还要求平台公共文件命令服务可达，不能以模块构建通过替代实际上传/预览联调。

PC 模板不默认授予执行提交权限；未来执行端需要独立装配该权限。没有权限的用户不能通过直接调用提交接口替代授权。后台自动任务生成也需要明确服务身份、授权与运维策略，不能靠绕过 AssetsHolder 的定时扫描代替。

三类统计补充接口：`POST /park/patrol/statistics/{points|people}/report` 返回周期、分组与总计；`POST /park/patrol/statistics/{points|people}/export?qualification=false` 导出XLSX，`qualification=true`导出时段完成合格率。均沿用 `patrol-report:query` 与计划资产 read，原列表接口保留给已部署调用。

项目与员工接入需同时验证应用 Scope、项目内查询、兄弟项目列表/详情拒绝、普通编辑禁止改归属，以及等级等配置必须归属项目、组织配置不可作为共享引用；员工执行需分别验证指定角色任务的角色及排班交集、全员任务及漏检申报的角色或班次条件。本地接入使用独立基础服务的公开只读命令；远端上线需同步发布基础服务的新员工契约，不能仅更新巡更 JAR。历史无归属数据仍须显式审查分配，不自动迁移。

## 应用角色与执行资格

巡更不创建或维护独立角色及成员，也不注册角色持久化实体或自建角色资产。角色仅来自当前巡更应用实例的应用角色；巡更提供 `POST /park/patrol/roles/_query` 只读目录，直接执行认证服务的 `authService:role` 命令，保留调用者认证、应用 Scope 和角色/人员资产权限。点位指派及规则、任务、排班、漏检与统计统一使用 `roleId` / `roleName`，没有旧自建角色映射或兼容路径。角色属于应用，点位、计划和排班继续属于项目，角色引用无需绑定某个项目。

本人执行使用认证服务构建的有效 role 维度，并精确匹配当前应用的 `applicationId`；管理范围不等于执行资格，也不要求普通巡更员拥有角色或用户维护权限。员工有效性、应用成员、项目资产、排班和时段仍需满足既有校验。排班模板列出当前项目有权使用的有效员工，角色成员取交集，未分配角色的员工也可独立排班。

角色目录复用现有 `authService:role` 分页命令，成员 ID 通过现有 `authService:user` 查询实时补齐；成员查询同时限定启用账号、当前应用成员、指定角色及调用者的 user 资产范围，不依赖角色投影返回成员，也不回退未过滤的旧成员快照。该方案只需更新巡更服务，无需为此升级共享认证服务或修改物业基础服务。数据库旧字段或旧表不作为查询来源，不沿用旧自建角色的测试指派。

## 组织资产权限兼容

巡更独立服务的 `PatrolAssetsConfiguration` 通过原 Bean 名替换组织及上下级权限提供者。
当前公共组件在账号具有多个应用维度但没有有效组织维度时，会生成目标为空的资产查询条件。
`EmptySafeOrgIncludeParentAssetsAccessSupport` 只对空组织的查询分支使用恒假条件，
保留其他租户、应用和创建人授权分支；有组织及写入操作继续使用公共组件行为。
该配置属于巡更启动服务，不要求将基础 manager 打入巡更，也不修改公共组件仓库。
公共组件修复后可以移除此兼容实现；回归须覆盖零个及多个非组织维度、有效组织和同名 Bean 替换。

## 巡更履行统计

`POST /park/patrol/statistics/overview`、`/overview/tasks`、
`/overview/detail` 和 `/overview/export` 统一从已生成、已授权的真实时段任务
统计，按任务归属日查询。点位日任务按项目、点位、归属日汇总，详情保留
真实时段、任务组及执行记录，不为统计重建业务任务。

总览同时展示应巡、有效完成、到期未完成及未到期剩余次数。
完成进度为有效完成／全部应巡；已截止任务完成率只使用已截止时段的有效完成／应巡。
有效完成包含审核补计，不等同于按时打卡率。无分母返回 null，页面及导出
显示“—”；项目总计先汇总分子分母，不平均项目百分比。项目对比、每日统计、
任务明细与 XLSX 使用相同口径。

漏检为已有有效完成但存在到期未完成要求；缺勤为所有时段截止仍无有效完成。
检查异常单独统计，不把已经完成的巡更改判为未完成。人员统计仅追溯真实
执行贡献，不把共享角色任务分摊为个人应巡次数或生成个人排名。
查询使用已有计划资产权限并限制关联执行范围，超出统计容量时明确拒绝，
不静默截断后输出不完整报表。

统计汇总只投影必要的任务和执行字段，不读取答案、图片和检查标准快照；
执行事实通过数据库子查询关联相同的已授权任务筛选，不逐批往返读取任务 ID。
详情仍返回完整执行快照。执行所属任务子查询使用独立别名，避免与计划权限子查询互相遮蔽。
H5 当天任务和本人漏检限制实际结果数量，不因无关历史计划超过数量上限而拒绝入口；
项目选择和原应用资产权限共同作用于事实的 `planId`，不会扩大到其他可见项目。

### PostgreSQL 查询索引

已有大数据量环境在巡更业务库逐条执行以下脚本；`CREATE INDEX CONCURRENTLY`
不能放入事务，也不能使用 `psql --single-transaction`。脚本不修改业务数据或权限：

- `deploy/patrol/20261106-query-performance.sql`：任务归属日、任务组排序和计划关联索引。
- `deploy/patrol/20261106-statistics-execution-covering.sql`：执行统计覆盖索引，避免查询答案/标准快照所在的执行主表；包含回退语句。
- `deploy/patrol/20261106-query-performance-low-resource.sql`：仅供半核等低资源测试库比较使用；不是生产默认配置，扩容后需重新核对计划并按脚本说明恢复。

建索引后核对 `pg_index.indisvalid`、`indisready`，并用实际授权范围及日期的
`EXPLAIN (ANALYZE, BUFFERS)` 验证扫描方式。`IF NOT EXISTS` 不会修复此前失败留下的同名无效索引，
需先确认并移除无效索引再重建。索引大小和首次请求耗时随数据及运行资源变化，不能以单次热查询承诺固定延迟。
