# 物业计费模块

业务由统一 property-management-service 装配，使用 JetLinks 2.20 响应式服务、SaaS登录和菜单动作权限。项目业务同时检查 organization 资产；基础数据只通过 property-base-core 的公开命令读取，不依赖基础 manager 或跨表访问。

## 本地与部署初始化

1. 按物业仓库说明配置被忽略的 application-local.yml，启动后由 EasyORM 创建业务表。
2. 在物业服务使用的 PostgreSQL 执行 `../property-base/sql/init-property-dictionaries.sql`，再执行本模块 `sql/init-finance-dictionaries.sql`（UTF-8）。如使用非 public schema，统一替换脚本中的 public.。
3. SQL 只补缺项，可重复执行，不覆盖已有名称、启停、排序和逻辑删除状态。收费来源、支付方式、费用类型来自旧代码真实枚举；欠费等级分类初始为空，应先在字典管理维护实际等级，再维护欠费通知等级配置。
4. 前端初始化 charging-management-ui 菜单和按钮权限，按职责分配计费管理权限及项目组织资产。税号为共享主档，项目通过独立关系使用公司；项目关联不会授予全局公司维护权。

命令行示例（连接参数由部署者提供，密码使用 PG 托管凭据或交互输入）：

```powershell
psql -h <数据库地址> -p <端口> -U <用户名> -d <数据库> -W -v ON_ERROR_STOP=1 -f modules/property-base/sql/init-property-dictionaries.sql
psql -h <数据库地址> -p <端口> -U <用户名> -d <数据库> -W -v ON_ERROR_STOP=1 -f modules/property-finance/sql/init-finance-dictionaries.sql
```

## 接口与引用约定

接口前缀 `/property/finance`。税号公司在 `/companies`；项目范围接口在 `/projects/{projectId}` 下，参数必须显式传递。新增、更新、逻辑删除使用业务入口，更新和删除必须携带当前版本，冲突返回409，不自动覆盖。公司与银行保持稳定ID，财务引用不能通过删除重建绕过。

新增公司并关联通过 `/companies/_create-and-bind/{projectId}` 在一笔事务完成；项目公司详情和候选查询通过项目权限入口，避免要求用户获得共享主档维护权限。每项目最多一个默认公司，先切换默认才允许解除原默认关系。银行和公司被入账规则或税目实际引用时拒绝删除；相关维护持公司锁后再锁从表，查询失败直接抛出，不按“无引用”处理。

税目和收费科目的Excel模板、解析及校验由后端提供，只接受Excel；先全量校验，再事务写入，失败包含行号、字段和原因。关键写入与算费使用MonoTracer。

## 活动设置

`/property/finance/projects/{projectId}/activities` 提供活动的直接新增、编辑、只读详情和逻辑删除，无申请及工作流。权限资源 `property-finance-activity` 的 `query/save/state/date/delete` 分别控制查询、配置、启停、延期或提前结束、删除；写入需要项目及全部优惠空间的资产权限，版本冲突返回409。

`GET /_options` 返回本项目可用标准、活动类型和授权空间；不要求取得标准维护菜单权限。活动类型复用 `promotion-type` 字典，默认SQL补充“充值赠送”，不覆盖既有状态。优惠范围使用来源空间ID，支持任意深度，不依赖楼栋、楼层等固定层级，名称及位置由基础公开命令解析。季度收费的充值和赠送月数均须为3的倍数。

`PUT /{id}/_state` 接受 `version/enabled`；`PUT /{id}/_extend` 与 `/_end` 接受 `version/endDate`，前者必须晚于原结束日，后者不得早于今天或开始日且须早于原结束日。`POST /{id}/logs/_query` 查询配置历史，删除后仍保留；配置与审计失败整笔回滚。列表不返回空间路径，完整详情及历史另校验全部目标空间读取权限。附件保存平台文件ID与名称，沿用平台鉴权文件能力。

活动引用的标准不能删除。活动配置与柜台充赠入账分别处理，不表示独立创建活动即发生资金入账。

柜台预缴报价位于 `/property/finance/projects/{projectId}/cashier/prepay/quotes`，`POST` 创建、`GET /{id}` 恢复原报价，复用 `property-finance-cashier:collect`。请求仅含 `requestId/settingId/payerRelationshipId/activityId/paidMonths/giftMonths`；普通预缴不传活动且赠送月数为0，活动档位必须匹配服务器配置。报价使用算费任务配置的业务时区，不接收客户端金额或业务日期。

`GET /property/finance/projects/{projectId}/cashier/prepay/_options?spaceId=...` 同样使用柜台 `collect` 权限，返回当前房屋有效收费设置、冻结公司和结算方式、当前所选付款人以及适用的未消费活动/档位。该接口不借用收费设置、活动维护权限，不返回原始快照、来源账号或其他房屋客户；停用、未下发、关系已结束、超出优惠空间及已消费活动不作为候选。单房屋超过200条有效设置或500项匹配活动时明确返回错误，避免静默截断。

报价保存十分钟，只允许原操作员在仍有项目、房屋写权限时读取；同请求重试恢复冻结结果，更换内容复用请求号返回409。金额、逐期日期和优惠通过字符串返回，完整计费与来源版本快照仅在后端保存，不开放通用编辑和删除接口。报价不生成应收、支付或活动消费，也不占用活动参与资格。

`POST /{id}/_confirm` 由柜台人工确认收款，请求为 `requestId/version/companyId/paidAt/tenders/remark/attachmentName/attachmentFileId`。支付方式和入账配置复用普通柜台规则，合计必须等于报价实收；房屋、付款人、活动及账期版本变化、过期或跨业务日的未确认报价返回409。确认按基础、公司、科目/设置、活动、应收、报价的顺序加锁，同一事务生成缺少的未来应收、应用逐期优惠、写实收及核销、占用活动资格并确认报价；任何一步失败整体回滚。确认后使用原请求重试可恢复原实收，查询报价返回 `paymentId`；重复确认不会生成第二笔支付。

预缴账期按整期结算，账期 `CLOSED` 保持后续日计提的完整本金，和财务月结独立；不以未来日期覆盖实际收款业务日期。零实收的优惠期仍保留账单与审计，不生成金额为零的支付来源。活动参与以项目、房屋和活动为唯一身份，多收费对象不能重复领取。成功参与后不能删除活动或修改优惠范围、标准、类型、档位及冲抵条件；名称、备注和附件可编辑，启停和结束日期通过专用动作调整。退款仅按逐期实际收款额度处理，赠送优惠不转为可退现金，原活动参与与优惠历史继续保留。

月/季度按自然账期及设置有效期逐期计算，沿用冻结公式和舍入。当前有效所选客户才可付款，关系须覆盖报价最早账期。符合活动冲抵条件的完整未付历史本金优先；已收或部分已收、拆分、逻辑删除和财务占用的账期保留占位并跳过，不重建。赠送体现为逐期优惠，不能当作可退现金余额。

## 自动结转后台配置

自动结转计划使用各自的日、周、月、年执行日和时区。后台默认每30秒扫描一次，启动后补跑当天已到达的槽位，并续跑数据库中未完成的批次；不会自动创建往日遗漏的新槽位。每轮每计划最多处理32笔，后续轮次继续处理；数据库租约防止多实例领取同一批次，单笔扣款复用稳定请求身份。

本地覆盖配置示例：

```yaml
property:
  finance:
    carry-job:
      enabled: true
      poll-seconds: 30 # 允许5～3600秒，与基础数据每小时同步独立
```

计划创建、编辑或启停时保存执行人的认证上限和应用范围，执行时重新读取当前身份并取权限交集，恢复原租户。执行人被删除、维护权限或房屋资产授权被收回时拒绝入账；无保存授权的旧计划需由有权限人员重新保存或启用。授权快照只在服务端保存，不通过详情或配置审计返回。`org.jetlinks:type=PropertyManagement,name=CarryForwardJob` 提供运行状态、成功/失败/跳过计数、最近时间及错误键；停机释放定时订阅和MBean。

计划与执行日志位于 `/property/finance/projects/{projectId}/carry-plans`。`GET /_options` 仅返回本项目已下发科目；`POST /{planId}/runs/_query` 和 `GET /{planId}/runs/{runId}` 查询批次，逻辑删除计划后历史仍保留。批次的 `/works/_query` 分页返回有空间读取权限的房屋明细，`GET /works/{workId}` 只读查看，`POST /works/{workId}/items/_query` 分页核对原账户入账结果；金额以字符串返回，不暴露后台授权、租户、配置原文和租约。

`POST /{planId}/runs/{runId}/_retry` 使用独立的 `property-finance-carry:retry` 按钮权限。仅有失败明细的已完成批次可以重试；原计划须启用、未删除且版本未变化，并校验全部失败房屋的空间写权限。重置失败明细与 `RUN_RETRY` 审计同事务，失败不部分提交。重试仍使用原批次、应收、账户和业务日期，已入账结果不会重复扣款；每轮上限后的剩余工作由后台继续处理。不能通过请求指定执行人、业务日期或金额。

## 柜台收款与实收查询

接口位于 `/property/finance/projects/{projectId}/cashier`，由 `property-finance-cashier` 的 `collect` 与 `query` 动作控制，并校验项目组织、每笔账单的空间资产权限。前端菜单为“收款管理 / 收银台、实收款管理”。

| 接口 | 用途 |
| --- | --- |
| `GET /_options` | 当前项目已关联公司、人工支付方式及PC入账银行候选 |
| `POST /payers/_query` | 按账单ID查询所选账单的收费对象交集，且必须仍是各房屋有效客户 |
| `POST /_preview` | 按业务日刷新应收，校验本次金额并返回确认令牌；不写账 |
| `POST /_collect` | 提交 `requestId`、`token` 及原预览输入，原子写入实收、核销、应收金额和审计 |
| `POST /payments/_query` | 按授权空间分页查询逐账单逐支付方式的实收明细 |
| `GET /payments/{id}` | 只读查看收款及核销明细；需要该收款单涉及的全部空间权限 |

人工收款支持现金、客户汇款、转账、POS，表示有权限人员确认已收款；非现金方式必须匹配当前项目、公司、PC来源和银行配置。接口不接受客户端传入支付成功状态。当前仅收银台收费，没有用户端APP；云亭收费和收银台开票入口不迁移。预收款和押金仍按各自账本处理，不用普通收款替代余额事实。

每次最多100笔账单、10种支付组合，允许部分收款和混合支付。输入金额及返回金额使用十进制字符串，按分逐笔分配，合计必须一致。未月结账单按与计费任务相同业务时区刷新当天应计；已财务月结账单保留原应收金额，仍可收取历史欠费。本次缴款另记实收流水。缴款人与原欠款客户独立保存，所选收费对象资格及各房屋当前有效记录在正式入账时重新校验。

同项目同 `requestId` 与相同输入返回原实收；改变输入、过期预览或并发版本冲突返回409。浏览器在发送确认前按账号、租户、应用和项目保留会话中的待确认请求，网络结果未知时复用原请求核对；不得以新的请求号重试收款。附件只保存平台文件ID和名称，下载沿用平台鉴权能力。

实收和核销记录不开放通用修改或删除。账单、资金流水和审计属于同一响应式事务，任一步失败整批回滚；实收查询按核销行授权后分页，不能从主单总额泄漏其他空间的收款。关键入账链使用 `MonoTracer`，没有新增常驻队列或内存任务。

## 收费对象与退款

收费设置的 `customerRelationshipIds` 必填，支持1至100位本房屋当前有效客户。每份设置保存完整对象快照，只生成一笔应收，所选任一有效对象可以柜台缴款，不分摊、不按对象重复计费。家庭模型及家庭代缴规则已经取消。既有单客户账单按原客户解析，历史快照不以当前客户或同房屋其他人替换。

退款接口位于 `/property/finance/projects/{projectId}/refunds`，权限 `property-finance-refund:refund/query`。`GET /_options` 提供人工方式；`POST /sources/_query` 仅读取已授权来源行及公司摘要；`POST /_preview` 预览，`POST /_confirm` 使用 `requestId/token/input` 原子确认，`POST /_query` 按空间授权分页，`GET /{id}` 查看整单只读详情。

退款保留原实收金额，单独记录退款主单和原核销来源明细，累计已退金额并恢复应收欠费，与审计同事务。部分退款按剩余可退额分配至分，尾差采用最大余数，不能因部分已退而超退其他来源。已开票占用需先在独立票据模块完成红冲；原收款公司不匹配、日期早于原收款、来源失效或余额不足拒绝。财务月结保留原应收金额，退款作为本次资金事实。

退款不设工作流申请；原旧系统由按钮控制的审核类业务仍按实际场景保留，不因“审核”名称统一裁掉。独立票据模块使用明确标识的模拟开票和红冲，不连接诺诺；活动只保留直接新增的活动设置。退款确认前保留会话原请求，结果未知时只复用原号核对；不可直接编辑或删除资金流水。

## 算费任务配置

房屋收费设置保留规则、房屋和客户快照，保存后在同一事务立即出账。自动任务独立于基础数据同步：生成应收00:00、每日计提00:10、账期关闭00:20、逾期计算00:30。关期默认关闭，不影响正常计提。部署到多节点时各节点保持相同业务时区。

可在被忽略的 `application-local.yml` 或部署环境配置中覆盖：

```yaml
property:
  finance:
    billing-job:
      enabled: true
      zone: Asia/Shanghai
      generate-at: "00:00"
      accrue-at: "00:10"
      close-enabled: false
      close-at: "00:20"
      late-fee-at: "00:30"
```

任务记录由EasyORM建表，每设置、任务类型和业务日只有一个持久身份。数据库租约协调多实例；单任务失败回滚其账单，其他任务继续处理。服务重启补跑当天已到点计划，并恢复等待任务及过期执行租约。失败任务在收费设置的“算费任务”中处理后重试，保留原业务日期；接口 `/projects/{projectId}/billing-tasks/_query` 与 `/{id}/_retry` 按项目和空间资产权限校验，分别复用收费设置的查询和生成应收按钮权限。

`org.jetlinks:type=PropertyManagement,name=BillingJob` MBean暴露运行、成功、失败、跳过、最近执行时间和稳定错误键，不暴露客户隐私或绕过权限的业务重试。后台以系统操作者和设置保存的租户执行冻结规则，不使用最近登录用户的上下文。轮询30秒只处理恢复和触发计划，单项超时5分钟、租约10分钟；账期唯一约束和设置行锁防止故障恢复重复出账。

手续费阶梯旧系统存在字段但未持久化、未找到计算消费者；当前配置预览按整笔金额匹配连续区间、百分比费率、保底封顶后四舍五入到分，作为明确补齐的规则，不表示已与支付入账联调。外部服务商目录和开票通道尚未接入时不生成假选项或假成功。

## 独立票据来源约束

发票与收据共用来源额度。应收单及其各次实收归一为同一应收来源；临时款的现金、银行卡等支付行归一到收款主单，不能从不同入口重复领取额度。应收按实际应收金额减已占额度计算，保留先票后款；临时款按扣除已退金额后的净实收减已占额度计算。

来源读取只使用历史房屋、客户、收费标准和税目快照，不查询当前资料替换历史名称或税率。快照缺失、项目或空间无权访问、来源删除或已拆分、实收与核销不一致均明确拒绝。单来源最多1000条实收行，超限拒绝，不截断后继续计算。正式开具时须先锁开票公司，再按固定顺序锁应收、实收行、资金账户与原存入来源控制账；来源读取本身不写票据或占用金额。

内部票据账本保存每张票据对各规范来源的占用事实，与来源计数和票据主单必须处于同一事务。相同请求重放不重复占用，金额或来源变化拒绝；作废、红冲按原分配释放一次并保留原因及操作者。临时款逐支付行保存占用分配，释放时恢复原行，不能挪用其他票据额度。有效占用仍沿应收和实收原有保护阻止退款。本账本不单独开放预约额度接口，也不代表已接入真实税务开票通道。

### 开票规则与预览

`GET /property/finance/projects/{projectId}/document-rule` 查询项目开票规则；`PUT` 携带 `version`、`timeLimitType`、`limitDays`、`maxReopenTimes`、`reason` 保存，版本冲突返回409，修改与日志同事务。未配置时返回自然年时效、最大重开0次和空版本，首次保存提交空版本；自定义天数须为1至36500，重开上限为空表示不限次数。切回自然年会清空原天数。规则不提供删除接口，红冲释放与重新开具的次数限制分别处理。

`POST /property/finance/projects/{projectId}/invoices/_preview` 与 `/receipts/_preview` 分别使用发票、收据的 `create` 动作权限，校验项目和空间资产。请求包含 `documentType`、`companyId`、`buyer`、`invoiceType`、`remark`、`items`；发票类型1为普票、2为专票，专票需购方税号，收据不提交发票类型。每行提交 `sourceType`、`sourceId`、`amount`、`collectionMethod`、`differenceAmount`、`voucher`。全额征收不提交凭证；差额征收必须提交合法扣除凭证、日期、足额金额和附件。所有金额以字符串传输，后台计算税率、税额和销方资料，不能由前端覆盖。

预览返回逐行金额、税额、购销方快照、开具场景和 `token`，不写票据、不占额度。批量来源须同项目、客户和销方快照；已收款发票受项目时效约束，未收应收保留先票后款。来源、版本、可用额度、规则或业务日变化会使预览指纹变化，正式开具须复算核对。流程审批、APP申请、诺诺通道和收银台开票入口不在这些接口内。

### 开具、模拟红冲与收据作废

`POST /property/finance/projects/{projectId}/invoices/_confirm` 和 `/receipts/_confirm` 携带 `requestId`、预览 `token` 及原 `input`。继续使用各自资源的 `create` 动作；`GET /{id}` 使用 `query` 动作读取只读详情，发票和收据路径不可互查。票据没有通用编辑、删除接口。

请求身份包含租户、项目、操作者、票据类型和操作入口。同请求同内容恢复原票据，不再次占用；相同请求号换内容返回409。成功请求重试先核对历史结果，再校验当前项目及全部冻结空间权限，不要求原客户仍处于当前房屋关联，也不以已被本请求占用的额度重新预览。新开具须复算指纹；票据主单、逐行历史快照、差额凭证、共享额度占用和操作审计在同一事务保存。

发票渠道为 `SIMULATED`，状态 `SIMULATED_ISSUED`，编号以 `SIM-` 开头，均不代表税务平台开票成功。`POST /invoices/{id}/_reverse` 使用 `reverse`（模拟红冲）动作，提交 `requestId`、原票 `version`、`reason`，建立 `SIMULATED_RED` 负金额关联红票，原票转为 `SIMULATED_REVERSED`。红票保留原购销方、来源、税务和凭证快照；红票金额、税额及不含税额为原值的相反数。原票、红票、占用释放和审计同事务；同请求重放只返回原结果。普通红冲不受重开次数限制，重新开具另行处理。

收据渠道为 `INTERNAL`，状态 `ISSUED`；`POST /receipts/{id}/_void` 使用 `void`（作废）动作，提交同样的请求号、版本和原因，作废后为 `VOIDED`，保留原金额及资料。保留旧付款关联限制：原开具来源是实收/临时款，或原应收后来已收款时，拒绝直接作废；不能通过改用应收别名绕过。电子收据打印与独立分配池见下文，付款关联处理入口按对应功能接入；预收、押金原存入使用下述 FUND_TOPUP 来源。

## 应收管理

应收接口位于 `/property/finance/projects/{projectId}/receivables`，查询与操作同时校验项目和空间资产权限。账单以已出账的房屋、客户和计费快照显示，客户结束关联不替换历史收费客户。

冻结、解冻和逻辑删除须提交账单版本与操作原因，状态和前后审计同事务保存；付款、代收、优惠、票据占用与财务月结保护不能通过通用CRUD绕过。冻结继续按原规则计提和计算逾期费用。逻辑删除保留账期身份，定时任务不会重建原账。

调整、结转减免、日期拆分及冻结、解冻、删除在锁原账或基础空间之前取得项目期间锁；批量删除在锁整批账单之前取得，内部单笔操作沿用同一事务。调整、拆分以本次落账业务日校验开放期间，参考计算日期不能绕过；状态维护按本次操作日期校验。下一开放日期可修改未结原账，已财务月结原账仍按原操作策略禁止调整、拆分和状态变更。关闭期间拒绝时不改金额、版本、拆分归档或审计，批量操作整体回滚；只读预览和通知打印不初始化期间控制行。

`POST /_export` 导出当前筛选且有权查看的账单，中文Excel金额使用文本保持精度；单次上限10000条，超限明确拒绝，应缩小范围。`POST /{id}/logs/_query` 分页查询操作记录，删除后仍可按原账单身份核对记录。

### 应收日期拆分与升级

日期拆分入口 `/{id}/split`，`GET /_options` 返回原收费客户和当前房屋客户，`POST /_preview` 只试算，`POST /` 携带 input 与 token 正式保存。分界日计入第一段，首段按已计提日期比例及所选元/角/分精度计算，第二段取差。预览后日期、客户、版本或业务日变化须重新预览。两子账、本账归档和日志同事务保存；已收款、冻结、支付或票据占用、财务月结等状态按原业务限制拒绝操作。

原账保留只读历史，列表默认显示子账。子账保留来源ID及独立区间快照，后续计提使用冻结公式的累计区间差，避免原计提快照覆盖拆分金额；自动任务沿来源链更新有效子账，不重建原账。

已有应收表的环境须在停服备份后、启动新代码前执行 `modules/property-finance/sql/migrate-receivable-split.sql`，将原自然账期唯一索引改为账单业务键唯一索引。脚本为 PostgreSQL（本服务配置使用 PostgreSQL），可重复执行；新库由EasyORM建表无需执行。使用非public schema时先统一替换。失败整笔回滚，切勿跳过错误继续启动。前端重新初始化应收菜单的“拆分”按钮权限并按需分配。


### 历史应收导入

应收工作台的历史导入按当前项目处理，入口为 `/property/finance/projects/{projectId}/receivables/imports`。`GET /template.xlsx` 返回后端中文模板及该项目有权查看的房屋客户、科目标准参考和下拉选项；`POST /` 上传Excel；`POST /_query` 分页查看批次记录。权限动作分别为 `import` 和 `imports`，部署前重新初始化对应菜单按钮并分配权限。

模板包含合同编号、房屋完整路径、客户名称、收费科目、收费标准、计费开始日期、计费结束日期、应收账期、应收日期、原应收、减免金额、实际应收、备注。除合同编号与备注外均必填，日期用 `yyyy-MM-dd`、账期用 `yyyy-MM`；金额非负且最多两位小数，原应收减减免必须等于实际应收。不依赖房屋收费设置，历史金额独立冻结，不用当前面积或标准价格重新计算。

单次最多500行、10MB，仅接受 `.xlsx`、`.xls`，不接受公式单元格。完整路径、有效房屋客户、项目已下发科目及其标准必须唯一匹配；同文件及重复上传的相同业务账单拒绝重复建账。所有行完整预检后在同一响应式事务中写入账单及审计，任何写入失败整批回滚。批次结果独立保留，校验错误包含Excel物理行号、字段和原因；失败后修正原文件重新上传。大文件应分批，不会静默截断或部分成功。

已有应收表环境须在备份停服后执行 `modules/property-finance/sql/migrate-historical-receivable.sql`，使历史账单可不填写 `setting_id` 并添加来源、批次、合同和账期字段。脚本针对PostgreSQL，可重复执行；如还未升级拆分账单业务键，先执行上一节的拆分升级脚本。全新数据库由EasyORM创建实体表。

## 票据历史与可开具来源查询

`POST /property/finance/projects/{projectId}/invoices/_query` 与 `/receipts/_query` 使用各自 `query` 权限，按整张票据分页。`POST /{id}/logs/_query` 分页查询操作日志；红票可查到生成它的红冲记录，蓝票保留开具和红冲记录。详情和日志均先校验当前项目及整票全部冻结空间的读取权限。列表在数据库分页和计数前排除含未授权空间的整票，调用方的 OR 条件不能扩大项目、租户或票据类型范围；购方抬头 `buyerName` 与来源客户名称分别冻结，可独立检索。红冲、作废及来源后续删除均不删除已出具历史。

`POST /invoices/sources/_query` 与 `/receipts/sources/_query` 使用对应 `create` 权限，输入 `sourceType`（`RECEIVABLE`、`TEMP_PAYMENT` 或 `FUND_TOPUP`）、可选 `companyId`、`customerId`、`spaceIds`、`keywords` 和分页参数。分页默认12、上限200，不接受来源别名或任意查询条件；仅返回当前项目全部相关空间均有保存权限的来源。临时款按支付主单分页，混合支付方式只出现一次。公司筛选使用 PostgreSQL JSONB 表达式匹配历史收费标准快照，不以当前标准替换历史销方。

候选返回冻结房屋、客户、科目、公司、税率以及字符串金额 `allowedAmount`、`paidAmount`、`availableAmount`。额度耗尽或发票已超时效的行保留显示，但 `selectable=false`，`unavailableCode` 明确区分额度不足与超期；收据不套用发票时效。损坏快照等异常明确拒绝本次查询，不能静默跳过。查询不占用额度、不写票据，提交时仍需预览和正式确认重新校验。历史、日志、候选均强制分页且不允许查询加锁。

### 模拟红冲重开

`POST /property/finance/projects/{projectId}/invoices/{id}/reopen/_preview` 和 `/_confirm` 使用独立 `property-finance-invoices:reopen` 动作。预览提交原票 `version`、购方 `buyer`、`invoiceType`、`remark` 和必填 `reason`；确认提交 `requestId`、预览 `token` 和原 `input`。来源、金额、税目及差额凭证由后端继承原票，客户端不能指定另一批账单或覆盖税率。专票仍必须提供购方税号。

已模拟开具的蓝票确认后同事务红冲并开具新蓝票；已红冲且尚未重开的蓝票可继续重开，不重复产生红票。预览只将原票实际占用可释放金额纳入可用额度，不写票据或额度。确认在公司及来源锁下复算指纹，旧额度释放、新占用、蓝红票、链关联和审计一起提交；任何失败全部回滚。

`rootDocumentId`、`previousDocumentId`、`reopenDocumentId` 和 `reopenCount` 分别记录根蓝票、前票、后继和累计重开次数，同一原票只允许一个后继。次数使用当前项目开票规则：0禁止重开、空值不限；普通红冲不受此次数限制。重开沿旧规则允许超过首次开票时效后纠错，不放宽首次开票的时效。原票及凭证快照永久保留，历史详情只读。

同请求重试先恢复已成功结果，再校验当前项目和全部冻结空间权限；不因自己的额度占用、已耗次数、原票版本变化或跨日重试再次红冲。相同请求号换内容返回409。此能力只模拟税务动作，不接诺诺、工作流、APP或收银台开票。

## 交账管理

项目接口为 `/property/finance/projects/{projectId}/handovers`，资源 `property-finance-handovers` 的 `query`、`create`、`approve`、`reject`、`unapprove`、`cancel` 动作分别控制查看、交账、审核、驳回、反审核和反交账，不接入工作流。新菜单初始化后需分配相应按钮权限。

待交账分为缴款整单、退款整单和独立预收/押金流水。缴款整单包含全部房屋及支付方式，不允许只交其中一行；已关联缴款或退款的资金流水不再次交账。发生金额与实际现金分别冻结：退款按负数，预收/押金冲抵和内部转换不重复计入现金。金额由后端原始流水计算，不接受前端合计覆盖。

`sources/{type}/_query`、`_preview`、`_confirm` 提供分页候选、只读预览和整批确认。每批1—100笔来源，版本、预览令牌、全部空间权限及唯一归属均验证后才落库；来源绑定、原存入保护、批次、明细及审计同事务提交。任一步失败全部回滚。同一请求号仅恢复相同载荷的原结果，恢复时仍重新校验项目、租户及全部冻结空间权限。

批次状态为待审核、已审核、已驳回和已反交账。待审核可审核、驳回或反交账，已审核须先反审核；驳回或反交账释放来源后，可重新交账，旧明细和操作日志保留。新交账按填写的交账日期校验开放期间，不能用服务器次日绕过；所有状态操作先取得同一期间锁，再锁来源及批次。批次所属日期已结或已标记月结后，审核、驳回、反审核和反交账均拒绝，不能等到下一开放期间再改原批次。已成功创建或动作的原请求仍可恢复并重新校验资产。已核销收据关联的来源不能释放。原存入已交账时不能撤销；解除交账与恢复撤销资格同事务。交账本身不增加收款、扣减余额或改变票据额度，不开放物理删除。

列表在分页与计数前按整单全部空间权限过滤，详情只读；确认及复核请求结果未知时，前端保留原请求并禁止切项目或修改载荷，恢复后再刷新。关键写入使用链路追踪，没有新增常驻后台任务。财务月结属于独立能力，不能以交账完成代替月结。

财务月结的内部来源准备器 `MonthClosingPreparation` 按服务端会计账期的实际起止日期核对整期资金，支持跨自然月的期间。它对完整来源逐房屋授权，并对照活动绑定、审核批次和冻结交账明细；关联损坏不能被当作已审核。发生金额、实际现金和未交账/待审核数量由后端汇总，关联缴款或退款的资金流水不重复统计。每期最多一万笔来源，超限明确拒绝；只保留逐笔摘要，避免同时保留整期全部房屋明细。

准备器全程只读，不创建会计账期、不写月结或审计。`allReviewed` 只表示已核对来源均已审核，不能代替可结账判断；期间顺序、结账日期、应收审核、持久化并发保护和原子关闭仍由正式月结入口负责，确认前必须在保护范围内重新核对。应收计费账期关闭与财务月结保持独立。

`FinancialPeriodGate` 提供租户、项目唯一的持久事务门闩，必须由已完成项目授权的业务入口在真实响应式事务中调用。锁序为财务期间、基础项目、公司及业务来源，锁保持到事务结束；框架无覆盖 upsert 负责首次并发初始化，不覆盖已结日期。控制行不开放 HTTP 维护或删除。普通收款、退款、预收/押金存入退回划转冲抵、反冲抵、撤销存入、实收转预存、临时收费和预缴确认，以输入的实际资金业务日期校验 `closedThrough`。开放账期仍可缴纳历史已结应收；原成功请求优先恢复原结果并重新检查资产权限，等待期间锁后再次查询成功结果，再校验新操作的日期和来源版本。预缴恢复须重新读取报价，不能重用等待前的状态。

自动结转在锁计划之前取得同一期间锁，包含只减免、不发生余额消费的路径；嵌套调用资金服务沿用本事务锁，不倒置计划、应收和期间的锁序。预览和候选查询不写控制行；失败操作回滚控制行初始化及其业务资金、余额和审计。锁链路使用平台追踪，无新增常驻任务。

独立票据的开具、红冲或作废、重开及收据核销，在公司、来源、额度账和主单锁之前取得期间锁，按本次操作日期校验开放期间。下一开放期间允许办理历史票据，也允许对历史已财务月结应收开具票据；原票和原金额快照保留，红票记录本次操作日期。收据原有的付款关联及已核销不能作废限制继续生效。原成功请求在后续关闭期间仍可恢复，并重新校验资产权限；重开在最外层取得期间锁，嵌套红冲沿用同一事务。

收费设置的新增、编辑、后继版本、批量保存、停止和逻辑删除，以及人工出账，在基础空间、科目、设置或应收锁之前取得同一期间锁。设置的实际生效开始日期和停止结束日期也必须开放，不能在新开放日回填已结配置。自动出账不要求操作员在线：只读加载持久设置并校验当前租户，再取得期间锁，随后锁设置并复核归属；审计使用系统任务身份，不伪造用户登录上下文。新生成应收的实际计费开始日期必须开放，缺失的已结期账单明确拒绝，已逻辑删除、拆分或财务月结的历史身份保持原规则，不重复生成或刷新已结金额。

历史应收导入在全表业务事务开始先取得期间锁，校验本次操作日期和每行计费开始日期；已结行返回Excel物理行号、日期字段及关闭原因，整批不写账单或审计，失败批次独立保留。正式会计账期、月结与反月结接口保持未开放，不能仅凭内部期间门闩代替正式结账。

## 电子收据编号与打印

电子收据在独立票据模块生成，不消费纸质票据分配池。新编号为 `SJ` + 开具业务时间（17位，含毫秒）+ 请求身份摘要前16位大写十六进制；数据库对全编号设置唯一约束，同一成功请求始终恢复原编号，旧收据号码保持原样。模拟发票仍使用明确的 `SIM-` 编号。

`GET /property/finance/projects/{projectId}/receipts/{id}/print.pdf` 使用独立的 `property-finance-receipts:print` 动作，返回 `application/pdf`、`inline` 和 `Cache-Control: no-store`。调用仍需本项目、租户及整张收据全部冻结房屋的读取权限，不接受发票ID，不发布公开文件链接。前端菜单同步后需给需要打印的角色分配打印按钮权限。

PDF按开具时的公司、购方、客户、房屋、科目、期间及金额快照生成。开具人取首次开具审计，不能被后续作废人的信息覆盖；实时档案变更或来源逻辑删除不改历史打印内容。重印不新增单据、不改变占用、余额及审计。已作废收据仍可查看和打印，各页均标明“已作废”；只有开具时已全部收款的收据显示“今收到 / 实收金额”，先票后款及混合来源使用中性的“收据金额”。

固定A5横向模板及中文常规字重字体随包发布，明细自动分页、重复表头和收据编号，金额大写全程采用精确十进制转换。字体及许可证见 `property-finance-manager/src/main/resources/receipt-templates/fonts`。渲染在 `boundedElastic` 隔离执行，模板不接受客户端HTML、图片或资源地址，所有业务文本转义并禁止引擎访问外部资源；读取快照有1000行上限。损坏快照返回明确冲突，渲染失败返回业务错误，不生成空白的成功文件。入口使用链路追踪，没有新增常驻后台任务或公开缓存。

## 票据分配与票据池

项目接口为 `/property/finance/projects/{projectId}/allocations`，资源 `property-finance-allocation` 分为 `query`、`save`、`delete`、`pool`（维护票据池）动作。支持票本分页、只读详情、多行多本新增、编辑、逻辑删除、号码分页和操作日志；不开放通用物理删除。领用人通过 SaaS 公开用户命令分页选择，保留调用者认证，仅返回有效账号的ID、姓名和用户名。票据类型与来源来自基础字典 `bill_type`、`bill_info_source`，部署时执行同目录 `sql/init-finance-dictionaries.sql`。

新增填写购入日期、领用人、票据类型、代码、来源、可选限额、本数、每本数量、起号、启用/回收及备注。后端计算连续止号，购入日期按填写保存。每行1—99本、每本1—9999张，正整数票号不超过12位，每批最多50行、100万号码，所有行先校验再写入。号码按2000行分片写入，同一租户、项目、类型、代码内不能重号；批内重叠、并发重叠或审计失败均整批回滚，冲突明确返回409。

编辑和删除使用票本行锁及版本校验，存在任一已用号码即拒绝整本编辑或删除。仅修改资料时保留号码独立废弃状态，调整号段时逻辑删除旧号码并建立新池；旧记录及日志保留。删除释放活动号段占用，允许重新分配。单号废弃/启用必须填写原因并使用号码版本，已使用号码不能操作；号码、票本废弃计数和审计同事务更新。票本恢复或启用不会自动启用此前独立废弃的号码。

分配池与电子收据自动编号独立，开具电子收据不扣减此池。查询强制分页，并固定租户、项目及未删除条件，不能由客户端查询条件覆盖。前端详情只读，号码状态操作使用独立确认弹窗，接口错误通过统一消息提示。关键写入有链路追踪，本功能没有新增常驻任务。

## 收据核销登记

`POST /property/finance/projects/{projectId}/receipts/_verify` 使用独立的 `property-finance-receipts:verify`（核销）按钮权限。请求包含 `requestId`、`items: [{id, version}]` 以及可选 `remark`（最多200字），每批1—100张且不可重复。单张、批量使用同一入口；菜单同步后需给操作人员分配核销按钮权限。此处核销是核对收据后的票据登记，不是应收资金核销，不改变票据金额、收款、余额、来源额度及开具快照，也不引入工作流。

只允许核销本项目、本租户下尚未作废、尚未核销且版本一致的收据；发票不能使用此入口。每张收据涉及的全部冻结空间均须具备保存权限。核销保存 `verified`、`verifiedAt`、`verifiedBy`、`verifiedName` 和 `verificationRemark`，历史空 `verified` 按未核销显示。整批按主单ID排序加锁，先检查所有票据再写入登记和各张 `VERIFY` 操作日志；任一版本、权限、状态或审计写入失败均整批回滚。

沿用原系统单向核销约束，不提供反核销；已核销收据不能作废。作废在最终取得主单锁后再次检查核销状态，避免并发产生既核销又作废的票据。成功请求可用原请求号及原载荷恢复结果，仍重新校验当前项目和整批空间权限；更换票号、版本或备注后复用请求号返回冲突，不重复登记日志。

前端在收据台账提供单张及批量核销，确认弹窗展示所选票号、购方和金额，并可填写备注。未知结果冻结原项目、批次、版本和请求号，刷新后从“恢复核销确认”继续查询原操作结果。详情只展示核销信息和操作日志，接口错误通过统一消息提示。窄屏取消表格操作列固定，防止遮挡票据编号。


## 预收与押金原存入票据

独立发票、收据的来源选择支持 `FUND_TOPUP`，`sourceId` 为原始资金流水ID。候选返回 `fundType`（`ADVANCE` 或 `DEPOSIT`），显示原存入房屋、客户、科目、时间及可开金额；收费柜台没有开票入口。仅正向人工收款的 `TOPUP` 可作为来源，退款、划转、冲抵、退回余额、撤销等动作不能冒充原存入。原来源已经消费、部分退款或转出时不再允许新开具，不能用该账户后来补足的余额替换原来源额度。

原存入在确认时冻结客户ID、资金类型和完整标准税快照，预览指纹包含这份资料。后续标准修改、停用、删除或客户结束关联不替换历史名称、税率和商品编码。缺少或损坏历史快照明确拒绝，不读取当前标准猜测补齐；该内部JSON不随普通资金详情或候选接口暴露。新增字段由平台实体建表能力维护。

有效发票和收据共享每笔 `FundCreditEntity.invoiceOccupiedAmount`，同时维护其账户占用；多笔原存入可合并开具，同账户计数按最新版本累计。公司、全部应收和实收之后，资金账户按ID排序锁定，再锁各原存入来源；占用、票据主单、明细和日志同事务。开具不改变余额、现金流水或来源原额，有效占用沿既有资金规则阻止退款、撤销与消费。模拟红冲按原来源释放控制账和账户计数，保留原票历史；任一步失败全部回滚。已付款关联的收据保留不能直接作废的限制。
