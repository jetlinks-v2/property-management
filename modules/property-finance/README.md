# 物业计费模块

Excel 导入模板、暂存与审批、数据防重及升级操作见 [收费导入部署与使用](../../deploy/finance/IMPORT.md)。

业务由独立 services/property-finance-service 装配，使用 JetLinks 2.20 响应式服务、SaaS登录和菜单动作权限。项目业务同时检查 organization 资产；基础数据只通过 property-base-core 的公开命令读取，不依赖基础 manager 或跨表访问。

操作人、修改人、收款员及审核人姓名保存操作当时认证用户的姓名，未维护姓名时回退为登录账号；身份与授权仍使用用户 ID。历史记录保留原姓名快照，用户后续改名不会批量改写审计记录。

## 本地与部署初始化

1. 按物业仓库说明配置被忽略的 application-local.yml，启动后由 EasyORM 创建业务表。
2. 在独立基础服务使用的 PostgreSQL 执行 `../property-base/sql/init-property-dictionaries.sql`，再在同一基础字典数据库执行本模块 `sql/init-finance-dictionaries.sql`（UTF-8）。如使用非 public schema，统一替换脚本中的 public.。
3. SQL 只补缺项，可重复执行，不覆盖已有名称、启停、排序和逻辑删除状态。收费来源、支付方式、费用类型来自旧代码真实枚举；欠费等级分类初始为空，应先在字典管理维护实际等级，再维护欠费通知等级配置。
4. 前端初始化 charging-management-ui 菜单和按钮权限，按职责分配计费管理权限及项目组织资产。税号为共享主档，项目通过独立关系使用公司；项目关联不会授予全局公司维护权。

命令行示例（连接参数由部署者提供，密码使用 PG 托管凭据或交互输入）：

```powershell
psql -h <数据库地址> -p <端口> -U <用户名> -d <数据库> -W -v ON_ERROR_STOP=1 -f modules/property-base/sql/init-property-dictionaries.sql
psql -h <数据库地址> -p <端口> -U <用户名> -d <数据库> -W -v ON_ERROR_STOP=1 -f modules/property-finance/sql/init-finance-dictionaries.sql
```

## 接口与引用约定

接口前缀 `/property/finance`。税号公司在 `/companies`；项目范围接口在 `/projects/{projectId}` 下，参数必须显式传递。新增、更新、逻辑删除使用业务入口，更新和删除必须携带当前版本，冲突返回409，不自动覆盖。公司与银行保持稳定ID，财务引用不能通过删除重建绕过。

新增公司并关联通过 `/companies/_create-and-bind/{projectId}` 在一笔事务完成；项目公司详情和候选查询通过项目权限入口，避免要求用户获得共享主档维护权限。每项目最多一个默认公司，先切换默认才允许解除原默认关系。银行和公司被入账规则或税目实际引用时拒绝删除；相关维护持公司锁后再锁从表，查询失败直接抛出，不按“无引用”处理。

税目和收费科目的Excel模板、解析及校验由后端提供，只接受Excel；先全量校验，再事务写入，失败包含行号、字段和原因。关键写入与算费使用MonoTracer。

## 收费概览

`POST /property/finance/overview/_query` 使用 `property-finance-overview:query` 功能权限，同时逐项校验项目 organization read 和空间 read 权限。请求为 `projectIds`（1～100个）、`startDate`、`endDate`（严格 `YYYY-MM-DD`，含首尾最多366天）；混入无权项目时整个请求失败，不返回部分汇总。

返回 `houses`（真末级空间、面积及字典房态）、`receivables`（摘要、科目、逾期账龄及欠费房屋数）、`cash`（收款与退款趋势）、`balances`（预收与押金当前余额）、`handover`（当前交账状态金额）及 `asOfDate`。金额是精确十进制字符串。日期仅筛选应收日期与现金业务日期，房态、余额和交账始终为当前值。超过90天的趋势按月，其余按日；图中缺失日期由前端补零。

财务统计复用应收/实收报表的正式来源、退款日期和冲抵口径，账户额外注入空间资产权限。基础房屋通过 `QueryPropertyHouseSummaryCommand` 获取，不跨库。财务查询串行运行于只读快照；基础服务有自己的只读快照，不承诺跨服务原子快照。任何来源失败直接报错，不能降级为零。此功能只读，无需升级 SQL；部署时同时更新基础服务 core/manager 和收费服务，并初始化概览菜单及授权。

## 活动设置

`/property/finance/projects/{projectId}/activities` 提供活动的直接新增、编辑、只读详情和逻辑删除，采用按钮审批，不接工作流。权限资源 `property-finance-activity` 的 `query/save/state/date/delete/approve/reject` 分别控制查询、配置、启停、延期或提前结束、删除及审批通过/驳回；写入需要项目及全部优惠空间的资产权限，版本冲突返回409。

`GET /_options` 返回本项目可用标准、活动类型和授权空间；不要求取得标准维护菜单权限。活动类型复用 `promotion-type` 字典，默认SQL补充“充值赠送”，不覆盖既有状态。优惠范围使用来源空间ID，支持任意深度，不依赖楼栋、楼层等固定层级，名称及位置由基础公开命令解析。季度收费的充值和赠送月数均须为3的倍数。

`PUT /{id}/_state` 接受 `version/enabled`；`PUT /{id}/_extend` 与 `/_end` 接受 `version/endDate`，前者必须晚于原结束日，后者不得早于今天或开始日且须早于原结束日。`POST /{id}/logs/_query` 查询配置历史，删除后仍保留；配置与审计失败整笔回滚。列表不返回空间路径，完整详情及历史另校验全部目标空间读取权限。附件保存平台文件ID与名称，沿用平台鉴权文件能力。

新增/编辑保存后为 `PENDING` 且停用；`POST /_approve`、`POST /_reject` 接受 `{items:[{id,version}],reason}`，原因必填，支持1–100条批量审批。通过为 `APPROVED` 并启用，驳回为 `REJECTED` 且停用；驳回可编辑重新提交。审批弹窗包含状态分页、名称搜索、单条/批量审批和只读详情。整批先校验版本、项目及全部优惠空间写权限，任一失败不写入，审批与审计同事务。待审批/驳回不能直接启用，柜台候选与报价同时排除；编辑不改已发生的消费快照。

已有库升级前停收费服务、备份，执行 `sql/migrate-activity-review.sql` 再启动。脚本仅将旧活动空审批状态承接为 `APPROVED`，保留原启停，不覆盖已存在的审批结果。新库由 EasyORM 建表。重新初始化收费菜单并分配 `approve/reject` 按钮权限；活动叶菜单保留原ID及URL，直接作为一级“活动设置”。优惠范围使用带搜索的任意层级空间树，勾选上级联动选中下级末端房间，取消某间房后上级半选，提交所选末端身份；既有上级范围在选择弹窗中展开为其下级末端。搜索勾选只变更可见房间，保留已选的隐藏房间。

活动引用的标准不能删除。活动配置与柜台充赠入账分别处理，不表示独立创建活动即发生资金入账。

柜台预缴报价位于 `/property/finance/projects/{projectId}/cashier/prepay/quotes`，`POST` 创建、`GET /{id}` 恢复原报价，复用 `property-finance-cashier:collect`。请求仅含 `requestId/settingId/payerRelationshipId/activityId/paidMonths/giftMonths`；普通预缴不传活动且赠送月数为0，活动档位必须匹配服务器配置。报价使用算费任务配置的业务时区，不接收客户端金额或业务日期。

`GET /property/finance/projects/{projectId}/cashier/prepay/_options?spaceId=...` 同样使用柜台 `collect` 权限，返回当前房屋有效收费设置、冻结公司和结算方式、当前所选付款人以及适用的未消费活动/档位。该接口不借用收费设置、活动维护权限，不返回原始快照、来源账号或其他房屋客户；停用、未下发、关系已结束、超出优惠空间及已消费活动不作为候选。单房屋超过200条有效设置或500项匹配活动时明确返回错误，避免静默截断。

报价保存十分钟，只允许原操作员在仍有项目、房屋写权限时读取；同请求重试恢复冻结结果，更换内容复用请求号返回409。金额、逐期日期和优惠通过字符串返回，完整计费与来源版本快照仅在后端保存，不开放通用编辑和删除接口。报价不生成应收、支付或活动消费，也不占用活动参与资格。

`POST /{id}/_confirm` 由柜台人工确认收款，请求为 `requestId/version/companyId/paidAt/tenders/remark/attachmentName/attachmentFileId`。支付方式和入账配置复用普通柜台规则，合计必须等于报价实收；房屋、付款人、活动及账期版本变化、过期或跨业务日的未确认报价返回409。确认按基础快照校验、公司、科目/设置、活动、应收、报价的顺序加锁，同一事务生成缺少的未来应收、应用逐期优惠、写实收及核销、占用活动资格并确认报价；任何一步失败整体回滚。确认后使用原请求重试可恢复原实收，查询报价返回 `paymentId`；重复确认不会生成第二笔支付。

预缴账期按整期结算，账期 `CLOSED` 保持后续日计提的完整本金，和财务月结独立；不以未来日期覆盖实际收款业务日期。零实收的优惠期仍保留账单与审计，不生成金额为零的支付来源。活动参与以项目、房屋和活动为唯一身份，多收费对象不能重复领取。成功参与后不能删除活动或修改优惠范围、标准、类型、档位及冲抵条件；名称、备注和附件可编辑，启停和结束日期通过专用动作调整。退款仅按逐期实际收款额度处理，赠送优惠不转为可退现金，原活动参与与优惠历史继续保留。

月/季度按自然账期及设置有效期逐期计算，沿用冻结公式和舍入。当前有效所选客户才可付款，关系须覆盖报价最早账期。符合活动冲抵条件的完整未付历史本金优先；已收或部分已收、拆分、逻辑删除和财务占用的账期保留占位并跳过，不重建。赠送体现为逐期优惠，不能当作可退现金余额。

## 自动结转后台配置

自动结转计划使用各自的日、周、月、年执行日和时区。后台默认每30秒扫描一次，启动后补跑当天已到达的槽位，并续跑数据库中未完成的批次；不会自动创建往日遗漏的新槽位。每轮每计划最多处理32笔，后续轮次继续处理；数据库租约防止多实例领取同一批次，单笔扣款复用稳定请求身份。

本地覆盖配置示例：

```yaml
property:
  finance:
    carry-job:
      enabled: true
      poll-seconds: 30 # 允许5～3600秒，与基础数据每小时同步独立
```

计划创建、编辑或启停时保存执行人的认证上限和应用范围，执行时重新读取当前身份并取权限交集，恢复原租户。执行人被删除、维护权限或房屋资产授权被收回时拒绝入账；无保存授权的旧计划需由有权限人员重新保存或启用。授权快照只在服务端保存，不通过详情或配置审计返回。`org.jetlinks:type=PropertyManagement,name=CarryForwardJob` 提供运行状态、成功/失败/跳过计数、最近时间及错误键；停机释放定时订阅和MBean。

计划与执行日志位于 `/property/finance/projects/{projectId}/carry-plans`。`GET /_options` 仅返回本项目已下发科目；`POST /{planId}/runs/_query` 和 `GET /{planId}/runs/{runId}` 查询批次，逻辑删除计划后历史仍保留。批次的 `/works/_query` 分页返回有空间读取权限的房屋明细，`GET /works/{workId}` 只读查看，`POST /works/{workId}/items/_query` 分页核对原账户入账结果；金额以字符串返回，不暴露后台授权、租户、配置原文和租约。

`POST /{planId}/runs/{runId}/_retry` 使用独立的 `property-finance-carry:retry` 按钮权限。仅有失败明细的已完成批次可以重试；原计划须启用、未删除且版本未变化，并校验全部失败房屋的空间写权限。重置失败明细与 `RUN_RETRY` 审计同事务，失败不部分提交。重试仍使用原批次、应收、账户和业务日期，已入账结果不会重复扣款；每轮上限后的剩余工作由后台继续处理。不能通过请求指定执行人、业务日期或金额。

## 柜台收款与实收查询

接口位于 `/property/finance/projects/{projectId}/cashier`，由 `property-finance-cashier` 的 `collect` 与 `query` 动作控制，并校验项目组织、每笔账单的空间资产权限。前端菜单为“收款管理 / 收银台、实收款管理”。

| 接口 | 用途 |
| --- | --- |
| `GET /_options` | 当前项目已关联公司、人工支付方式及PC入账银行候选 |
| `POST /payers/_query` | 按账单ID查询所选账单的收费对象交集，且必须仍是各房屋有效客户 |
| `POST /_preview` | 按业务日刷新应收，校验本次金额并返回确认令牌；不写账 |
| `POST /_collect` | 提交 `requestId`、`token` 及原预览输入，原子写入实收、核销、应收金额和审计 |
| `POST /payments/_query` | 按授权空间分页查询逐账单逐支付方式的实收明细 |
| `GET /payments/{id}` | 只读查看收款及核销明细；需要该收款单涉及的全部空间权限 |

人工收款支持现金、客户汇款、转账、POS，表示有权限人员确认已收款；非现金方式必须匹配当前项目、公司、PC来源和银行配置。接口不接受客户端传入支付成功状态。当前仅收银台收费，没有用户端APP；云亭收费和收银台开票入口不迁移。预收款和押金仍按各自账本处理，不用普通收款替代余额事实。

每次最多100笔账单、10种支付组合，允许部分收款和混合支付。输入金额及返回金额使用十进制字符串，按分逐笔分配，合计必须一致。未月结账单按与计费任务相同业务时区刷新当天应计；已财务月结账单保留原应收金额，仍可收取历史欠费。本次缴款另记实收流水。缴款人与原欠款客户独立保存，所选收费对象资格及各房屋当前有效记录在正式入账时重新校验。

同项目同 `requestId` 与相同输入返回原实收；改变输入、过期预览或并发版本冲突返回409。浏览器在发送确认前按账号、租户、应用和项目保留会话中的待确认请求，网络结果未知时复用原请求核对；不得以新的请求号重试收款。附件只保存平台文件ID和名称，下载沿用平台鉴权能力。

实收和核销记录不开放通用修改或删除。账单、资金流水和审计属于同一响应式事务，任一步失败整批回滚；实收查询按核销行授权后分页，不能从主单总额泄漏其他空间的收款。关键入账链使用 `MonoTracer`，没有新增常驻队列或内存任务。

## 收费对象与退款

收费设置的 `customerRelationshipIds` 必填，支持1至100位本房屋当前有效客户。每份设置保存完整对象快照，只生成一笔应收，所选任一有效对象可以柜台缴款，不分摊、不按对象重复计费。家庭模型及家庭代缴规则已经取消。既有单客户账单按原客户解析，历史快照不以当前客户或同房屋其他人替换。

退款接口位于 `/property/finance/projects/{projectId}/refunds`，权限 `property-finance-refund:refund/query`。`GET /_options` 提供人工方式；`POST /sources/_query` 仅读取已授权来源行及公司摘要；`POST /_preview` 预览，`POST /_confirm` 使用 `requestId/token/input` 保存待审核申请（不立即退款），`POST /_query` 按空间授权分页，`GET /{id}` 查看整单只读详情。

退款保留原实收金额，单独记录退款主单和原核销来源明细，累计已退金额并恢复应收欠费，与审计同事务。部分退款按剩余可退额分配至分，尾差采用最大余数，不能因部分已退而超退其他来源。已开票占用需先在独立票据模块完成红冲；原收款公司不匹配、日期早于原收款、来源失效或余额不足拒绝。财务月结保留原应收金额，退款作为本次资金事实。

退款不接工作流，保留按钮审核。统一申请台账 `/property/finance/projects/{projectId}/refund-applications` 提供分页、详情、日志、待审修改（`save`）、确认退款（`approve`）和审核不通过（`reject`）。普通款、临时款、预收和押金退还统一先占可退额度；申请不动账，审核成功才执行原资金链路；驳回释放占额。修改金额重新校验并原子调整占额，版本冲突拒绝覆盖。重复确认复用原请求号且不重复退钱。独立票据模块提供开票和红冲，当前不连接诺诺税务通道，界面与权限名称统一使用业务名称；活动设置新增/编辑后通过按钮审批生效。退款确认前保留会话原请求，结果未知时只复用原号核对；不可直接编辑或删除资金流水。

## 算费任务配置

房屋收费设置保存规则、房屋和客户快照后进入待审批；审批通过才在同一事务生成已审核通过的应收，之后直接参与收款，不再二次审核普通账单。自动任务独立于基础数据同步：生成应收00:00、每日计提00:10、账期关闭00:20、逾期计算00:30。关期默认关闭，不影响正常计提。部署到多节点时各节点保持相同业务时区。

可在被忽略的 `application-local.yml` 或部署环境配置中覆盖：

```yaml
property:
  finance:
    billing-job:
      enabled: true
      zone: Asia/Shanghai
      generate-at: "00:00"
      accrue-at: "00:10"
      close-enabled: false
      close-at: "00:20"
      late-fee-at: "00:30"
```

任务记录由EasyORM建表，每设置（或无设置的历史根账）、任务类型和业务日只有一个持久身份。历史账任务的 `receivableId` 与普通任务的 `settingId` 二选一，恢复时仍使用原业务日。数据库租约协调多实例；单任务失败回滚其账单，其他任务继续处理。服务重启补跑当天已到点计划，并恢复等待任务及过期执行租约。失败任务在收费设置的“算费任务”中处理后重试，保留原业务日期；接口 `/projects/{projectId}/billing-tasks/_query` 与 `/{id}/_retry` 按项目和空间资产权限校验，分别复用收费设置的查询和生成应收按钮权限。

`org.jetlinks:type=PropertyManagement,name=BillingJob` MBean暴露运行、成功、失败、跳过、最近执行时间和稳定错误键，不暴露客户隐私或绕过权限的业务重试。后台以系统操作者和设置/正式账单保存的租户执行冻结规则，不使用最近登录用户的上下文。轮询30秒只处理恢复和触发计划，单项超时5分钟、租约10分钟；账期唯一约束和设置行锁防止故障恢复重复出账。

手续费阶梯旧系统存在字段但未持久化、未找到计算消费者；当前配置预览按整笔金额匹配连续区间、百分比费率、保底封顶后四舍五入到分，作为明确补齐的规则，不表示已与支付入账联调。外部服务商目录和开票通道尚未接入时不生成假选项或假成功。

## 独立票据来源约束

发票与收据共用来源额度。应收单及其各次实收归一为同一应收来源；临时款的现金、银行卡等支付行归一到收款主单，不能从不同入口重复领取额度。应收按实际应收金额减已占额度计算，保留先票后款；临时款按扣除已退金额后的净实收减已占额度计算。

来源读取只使用历史房屋、客户、收费标准和税目快照，不查询当前资料替换历史名称或税率。快照缺失、项目或空间无权访问、来源删除或已拆分、实收与核销不一致均明确拒绝。单来源最多1000条实收行，超限拒绝，不截断后继续计算。正式开具时须先锁开票公司，再按固定顺序锁应收、实收行、资金账户与原存入来源控制账；来源读取本身不写票据或占用金额。

内部票据账本保存每张票据对各规范来源的占用事实，与来源计数和票据主单必须处于同一事务。相同请求重放不重复占用，金额或来源变化拒绝；作废、红冲按原分配释放一次并保留原因及操作者。临时款逐支付行保存占用分配，释放时恢复原行，不能挪用其他票据额度。有效占用仍沿应收和实收原有保护阻止退款。本账本不单独开放预约额度接口，也不代表已接入真实税务开票通道。

### 开票规则与预览

`GET /property/finance/projects/{projectId}/document-rule` 查询项目开票规则；`PUT` 携带 `version`、`timeLimitType`、`limitDays`、`maxReopenTimes`、`reason` 保存，版本冲突返回409，修改与日志同事务。未配置时返回自然年时效、最大重开0次和空版本，首次保存提交空版本；自定义天数须为1至36500，重开上限为空表示不限次数。切回自然年会清空原天数。规则不提供删除接口，红冲释放与重新开具的次数限制分别处理。

`POST /property/finance/projects/{projectId}/invoices/_preview` 与 `/receipts/_preview` 分别使用发票、收据的 `create` 动作权限，校验项目和空间资产。请求包含 `documentType`、`companyId`、`buyer`、`invoiceType`、`remark`、`items`；发票类型1为普票、2为专票，专票需购方税号，收据不提交发票类型。每行提交 `sourceType`、`sourceId`、`amount`、`collectionMethod`、`differenceAmount`、`voucher`。全额征收不提交凭证；差额征收必须提交合法扣除凭证、日期、足额金额和附件。所有金额以字符串传输，后台计算税率、税额和销方资料，不能由前端覆盖。

预览返回逐行金额、税额、购销方快照、开具场景和 `token`，不写票据、不占额度。批量来源须同项目、客户和销方快照；已收款发票受项目时效约束，未收应收保留先票后款。来源、版本、可用额度、规则或业务日变化会使预览指纹变化，正式开具须复算核对。流程审批、APP申请、诺诺通道和收银台开票入口不在这些接口内。

### 开具、红冲与收据作废

`POST /property/finance/projects/{projectId}/invoices/_confirm` 和 `/receipts/_confirm` 携带 `requestId`、预览 `token` 及原 `input`。继续使用各自资源的 `create` 动作；`GET /{id}` 使用 `query` 动作读取只读详情，发票和收据路径不可互查。票据没有通用编辑、删除接口。

请求身份包含租户、项目、操作者、票据类型和操作入口。同请求同内容恢复原票据，不再次占用；相同请求号换内容返回409。成功请求重试先核对历史结果，再校验当前项目及全部冻结空间权限，不要求原客户仍处于当前房屋关联，也不以已被本请求占用的额度重新预览。新开具须复算指纹；票据主单、逐行历史快照、差额凭证、共享额度占用和操作审计在同一事务保存。

发票渠道为 `SIMULATED`，状态 `SIMULATED_ISSUED`，编号以 `SIM-` 开头，均不代表税务平台开票成功。`POST /invoices/{id}/_reverse` 使用 `reverse`（红冲）动作，提交 `requestId`、原票 `version`、`reason`，建立 `SIMULATED_RED` 负金额关联红票，原票转为 `SIMULATED_REVERSED`。红票保留原购销方、来源、税务和凭证快照；红票金额、税额及不含税额为原值的相反数。原票、红票、占用释放和审计同事务；同请求重放只返回原结果。普通红冲不受重开次数限制，重新开具另行处理。

收据渠道为 `INTERNAL`，状态 `ISSUED`；`POST /receipts/{id}/_void` 使用 `void`（作废）动作，提交同样的请求号、版本和原因，作废后为 `VOIDED`，保留原金额及资料。保留旧付款关联限制：原开具来源是实收/临时款，或原应收后来已收款时，拒绝直接作废；不能通过改用应收别名绕过。电子收据打印与独立分配池见下文，付款关联处理入口按对应功能接入；预收、押金原存入使用下述 FUND_TOPUP 来源。

## 应收管理

应收接口位于 `/property/finance/projects/{projectId}/receivables`，查询与操作同时校验项目和空间资产权限。账单以已出账的房屋、客户和计费快照显示，客户结束关联不替换历史收费客户。

冻结、解冻和逻辑删除须提交账单版本与操作原因，状态和前后审计同事务保存；付款、代收、优惠、票据占用与财务月结保护不能通过通用CRUD绕过。冻结继续按原规则计提和计算逾期费用。逻辑删除保留账期身份，定时任务不会重建原账。

调整、结转减免、日期拆分及冻结、解冻、删除在锁原账或基础空间之前取得项目期间锁；批量删除在锁整批账单之前取得，内部单笔操作沿用同一事务。调整、拆分以本次落账业务日校验开放期间，参考计算日期不能绕过；状态维护按本次操作日期校验。下一开放日期可修改未结原账，已财务月结原账仍按原操作策略禁止调整、拆分和状态变更。关闭期间拒绝时不改金额、版本、拆分归档或审计，批量操作整体回滚；只读预览和通知打印不初始化期间控制行。

`POST /_export` 导出当前筛选且有权查看的账单，中文Excel金额使用文本保持精度；单次上限10000条，超限明确拒绝，应缩小范围。`POST /{id}/logs/_query` 分页查询操作记录，删除后仍可按原账单身份核对记录。

### 应收日期拆分与升级

日期拆分入口 `/{id}/split`，`GET /_options` 返回原收费客户和当前房屋客户，`POST /_preview` 只试算，`POST /` 携带 input 与 token 创建待审批申请，返回申请记录，不立即拆分。分界日计入第一段，首段按已计提日期比例及所选元/角/分精度计算，第二段取差。预览后日期、客户、版本或业务日变化须重新预览。审批通过后两子账、本账归档、审批状态和日志同事务保存；已收款、冻结、支付或票据占用、财务月结等状态按原业务限制拒绝操作。

原账保留只读历史，列表默认显示子账。子账保留来源ID及独立区间快照，后续计提使用冻结公式的累计区间差，避免原计提快照覆盖拆分金额；自动任务沿来源链更新有效子账，不重建原账。

已有应收表的环境须在停服备份后、启动新代码前执行 `modules/property-finance/sql/migrate-receivable-split.sql`，将原自然账期唯一索引改为账单业务键唯一索引。脚本为 PostgreSQL（本服务配置使用 PostgreSQL），可重复执行；新库由EasyORM建表无需执行。使用非public schema时先统一替换。失败整笔回滚，切勿跳过错误继续启动。前端重新初始化应收菜单的“拆分”按钮权限并按需分配。


### 调整及日期拆分审批

应收行菜单保留详情、操作记录、调整、日期拆分、冻结/解冻；审核、驳回、删除不放在行菜单。普通应收不再提供独立审核、驳回、反审核入口；账单审核结果承接收费设置或历史导入审批，不能与变更申请审批混用。

`POST /{id}/adjustment`、`POST /{id}/split` 都提交已有预览的 `{input, token}`，仅创建 `PENDING` 申请，返回申请身份、版本和状态。提交仍使用 `adjust`、`split` 权限，重复待审批申请明确返回409。同一账单已有待审批调整或拆分时，必须先处理原申请。

独立“审批”按钮打开变更申请列表，可按项目、房屋、申请类型、待审批/已通过/已驳回筛选及分页。接口位于 `/property/finance/projects/{projectId}/receivables/changes`：

- `POST /_query` 使用 `query` 权限；空间资产权限在分页与统计前注入。
- `GET /{id}` 使用 `query` 权限，返回 `{record, input, preview, before}`，以申请时冻结的账单、表单及前后金额供复核，详情只读。
- `POST /{id}/_approve`、`POST /{id}/_reject` 使用现有 `approve`、`reject` 按钮权限，提交 `{version, reason}`，原因必填。沿用已有按钮ID，无需增加权限动作；未分配者仍不能审批。

批准时按项目期间→申请→原账/基础空间的锁顺序，在同一事务中核对申请版本、源账版本、当前开放期间、空间权限、客户关系及业务操作限制，复用原调整/拆分规则实际落账，随后保存审批人、时间、原因及操作记录。任何金额写入、归档或审计失败均回滚本次审批。并发或重复批准最多一次生效，冲突明确返回409。驳回只更新申请和审计，不改原账；允许驳回原账已变化或已关期的申请。

等待审批不会锁住日常收款和计提。源账被收款、计提、冻结等操作修改后，批准拒绝，须驳回并按最新账单重新申请；跨日但源版本未变时也会复算并比较申请金额及区间，金额变化同样拒绝，不能静默按新金额批准。应收关期任务遇到该账单待审批申请时明确失败，处理申请后从算费任务重试。内部自动结转的减免仍由系统应用服务直接执行，不伪造人工申请。

已有库在拆分及历史导入升级后，还须停服备份并执行 `modules/property-finance/sql/migrate-receivable-change-review.sql`，再启动新后端。脚本新建申请表、增加账单冻结租户及历史任务的 `receivable_id`，不改变存量金额或审核状态。归属只从已有设置和项目期间记录回填，不能明确唯一租户时整笔回滚，需人工核对归属后重跑；不能把未知租户写成默认租户。新库由 EasyORM 建表。

```powershell
psql -h <数据库地址> -p <端口> -U <用户名> -d <收费数据库> -W -v ON_ERROR_STOP=1 -f modules/property-finance/sql/migrate-receivable-change-review.sql
```

### 算费与旧系统的对应约束

生成、计提、关期、滞纳金的默认触发时间分别为00:00、00:10、00:20、00:30，关期默认关闭，可配置时区。自然账期、公式中的时间变量、按日折算、金额精度及尾数处理沿用旧规则：含月数变量的公式不再次按天折算；不含时间变量才按覆盖区间比例计提。跨月折算使用精确月份权重，拆分后用同一根区间的累计差计算子账，防止尾差重复。收费对象可多选但金额不分摊。

已关期账单不再次计提本金；尚未到结束日的账单不提前关期。冻结继续按旧规则计提和计逾期；财务月结、支付占用、全额结清保护仍生效。普通任务沿设置查找根账和拆分后的有效子账；无设置的历史导入根账单独建立持久任务，导入冻结本金不被现行标准覆盖。滞纳金按累计值替换，不重复叠加；累计欠费基数排除先前滞纳金，避免同日重跑复利。未配置逾期规则、单独锁定滞纳金和已结清账单遵守已有规则。

### 历史应收导入

应收工作台的历史导入按当前项目处理，入口为 `/property/finance/projects/{projectId}/receivables/imports`。`GET /template.xlsx` 返回后端中文模板及该项目有权查看的房屋客户、科目标准参考和下拉选项；`POST /` 上传Excel；`POST /_query` 分页查看批次记录。权限动作分别为 `import` 和 `imports`，部署前重新初始化对应菜单按钮并分配权限。

模板包含合同编号、房屋完整路径、客户名称、收费科目、收费标准、计费开始日期、计费结束日期、应收账期、应收日期、原应收、减免金额、实际应收、备注。除合同编号与备注外均必填，日期用 `yyyy-MM-dd`、账期用 `yyyy-MM`；金额非负且最多两位小数，原应收减减免必须等于实际应收。不依赖房屋收费设置，历史金额独立冻结，不用当前面积或标准价格重新计算。

单次最多500行、10MB，仅接受 `.xlsx`、`.xls`，不接受公式单元格。完整路径、有效房屋客户、项目已下发科目及其标准必须唯一匹配；同文件及重复上传的相同业务账单拒绝重复建账。所有行完整预检后在同一响应式事务中写入待审核明细及暂存审计，任何写入失败整批回滚。待审核数据不进入正式应收、收银和统计；审核通过才发布正式账单，驳回保留明细及原因。批次结果独立保留，校验错误包含Excel物理行号、字段和原因；失败后修正原文件重新上传。大文件应分批，不会静默截断或部分成功。

已有应收表环境须在备份停服后执行 `modules/property-finance/sql/migrate-historical-receivable.sql`，使历史账单可不填写 `setting_id` 并添加来源、批次、合同和账期字段。脚本针对PostgreSQL，可重复执行；如还未升级拆分账单业务键，先执行上一节的拆分升级脚本。全新数据库由EasyORM创建实体表。

导入审核提供批次与明细两种方式：`POST /{recordId}/lines/_query` 按房屋、客户及状态分页查询；`POST /{recordId}/_approve`、`/_reject` 接收 `{version, reason, items:[{id,version}]}`，`items` 为空处理本批全部待审行；`POST /_approve`、`/_reject` 接收 `{records:[{id,version}], reason}`，一次最多100批。明细一次最多选100行；整批审核仍可处理本文件最多500行。审核与驳回复用应收菜单已有 `approve`、`reject` 按钮权限，查询明细使用 `imports`，服务端重新校验项目与每个房屋资产。

版本过期、重复账单或任何一行失败会回滚本次全部审核（含多批次），不得自动重试覆盖。批准前重新校验会计期间；驳回不入账，可用于结束已关账期间的待审数据。待审、已通过、已驳回、失败分别查询，旧版本 `SUCCESS` 记录仍按已导入展示，不追溯改成待审核。混合明细决定的批次在仍有待审时保持待审核，全部完成后有通过即标通过，计数同时保留已驳回数量。

已有部署还须在停服备份后对**收费服务数据库**执行以下升级脚本，之后重启收费后端。先完成上面的拆分与历史应收升级；新库由 EasyORM 创建暂存表，无需手工建表。非 `public` schema 先统一替换脚本中的 schema。

```powershell
psql -h <数据库地址> -p <端口> -U <用户名> -d <收费数据库> -W -v ON_ERROR_STOP=1 -f modules/property-finance/sql/migrate-historical-import-review.sql
```

应收列表和导出共用正式金额、账单快照单价与用量、真实缴款日期及开票净税额；历史导入未提供的单价和用量显示空值，未开票不假算销项税。部分回款继续计逾期，结清后停在实际缴款日；页面“金额计算截至”表示持久金额实际计算日，不等同于浏览器当天。

## 票据历史与可开具来源查询

`POST /property/finance/projects/{projectId}/invoices/_query` 与 `/receipts/_query` 使用各自 `query` 权限，按整张票据分页。`POST /{id}/logs/_query` 分页查询操作日志；红票可查到生成它的红冲记录，蓝票保留开具和红冲记录。详情和日志均先校验当前项目及整票全部冻结空间的读取权限。列表在数据库分页和计数前排除含未授权空间的整票，调用方的 OR 条件不能扩大项目、租户或票据类型范围；购方抬头 `buyerName` 与来源客户名称分别冻结，可独立检索。红冲、作废及来源后续删除均不删除已出具历史。

`POST /invoices/sources/_query` 与 `/receipts/sources/_query` 使用对应 `create` 权限，输入 `sourceType`（`RECEIVABLE`、`TEMP_PAYMENT` 或 `FUND_TOPUP`）、可选 `companyId`、`customerId`、`spaceIds`、`keywords` 和分页参数。分页默认12、上限200，不接受来源别名或任意查询条件；仅返回当前项目全部相关空间均有保存权限的来源。临时款按支付主单分页，混合支付方式只出现一次。公司筛选使用 PostgreSQL JSONB 表达式匹配历史收费标准快照，不以当前标准替换历史销方。

候选返回冻结房屋、客户、科目、公司、税率以及字符串金额 `allowedAmount`、`paidAmount`、`availableAmount`。额度耗尽或发票已超时效的行保留显示，但 `selectable=false`，`unavailableCode` 明确区分额度不足与超期；收据不套用发票时效。损坏快照等异常明确拒绝本次查询，不能静默跳过。查询不占用额度、不写票据，提交时仍需预览和正式确认重新校验。历史、日志、候选均强制分页且不允许查询加锁。

### 红冲重开

`POST /property/finance/projects/{projectId}/invoices/{id}/reopen/_preview` 和 `/_confirm` 使用独立 `property-finance-invoices:reopen` 动作。预览提交原票 `version`、购方 `buyer`、`invoiceType`、`remark` 和必填 `reason`；确认提交 `requestId`、预览 `token` 和原 `input`。来源、金额、税目及差额凭证由后端继承原票，客户端不能指定另一批账单或覆盖税率。专票仍必须提供购方税号。

已模拟开具的蓝票确认后同事务红冲并开具新蓝票；已红冲且尚未重开的蓝票可继续重开，不重复产生红票。预览只将原票实际占用可释放金额纳入可用额度，不写票据或额度。确认在公司及来源锁下复算指纹，旧额度释放、新占用、蓝红票、链关联和审计一起提交；任何失败全部回滚。

`rootDocumentId`、`previousDocumentId`、`reopenDocumentId` 和 `reopenCount` 分别记录根蓝票、前票、后继和累计重开次数，同一原票只允许一个后继。次数使用当前项目开票规则：0禁止重开、空值不限；普通红冲不受此次数限制。重开沿旧规则允许超过首次开票时效后纠错，不放宽首次开票的时效。原票及凭证快照永久保留，历史详情只读。

同请求重试先恢复已成功结果，再校验当前项目和全部冻结空间权限；不因自己的额度占用、已耗次数、原票版本变化或跨日重试再次红冲。相同请求号换内容返回409。此能力只模拟税务动作，不接诺诺、工作流、APP或收银台开票。

## 交账管理

项目接口为 `/property/finance/projects/{projectId}/handovers`，资源 `property-finance-handovers` 的 `query`、`create`、`approve`、`reject`、`unapprove`、`cancel` 动作分别控制查看、交账、审核、驳回、反审核和反交账，不接入工作流。新菜单初始化后需分配相应按钮权限。

待交账分为缴款整单、退款整单和独立预收/押金流水。缴款整单包含全部房屋及支付方式，不允许只交其中一行；已关联缴款或退款的资金流水不再次交账。发生金额与实际现金分别冻结：退款按负数，预收/押金冲抵和内部转换不重复计入现金。金额由后端原始流水计算，不接受前端合计覆盖。

`sources/{type}/_query`、`_preview`、`_confirm` 提供分页候选、只读预览和整批确认。每批1—100笔来源，版本、预览令牌、全部空间权限及唯一归属均验证后才落库；来源绑定、原存入保护、批次、明细及审计同事务提交。任一步失败全部回滚。同一请求号仅恢复相同载荷的原结果，恢复时仍重新校验项目、租户及全部冻结空间权限。

批次状态为待审核、已审核、已驳回和已反交账。待审核可审核、驳回或反交账，已审核须先反审核；驳回或反交账释放来源后，可重新交账，旧明细和操作日志保留。新交账按填写的交账日期校验开放期间，不能用服务器次日绕过；所有状态操作先取得同一期间锁，再锁来源及批次。批次所属日期已结或已标记月结后，审核、驳回、反审核和反交账均拒绝，不能等到下一开放期间再改原批次。已成功创建或动作的原请求仍可恢复并重新校验资产。已核销收据关联的来源不能释放。原存入已交账时不能撤销；解除交账与恢复撤销资格同事务。交账本身不增加收款、扣减余额或改变票据额度，不开放物理删除。

列表在分页与计数前按整单全部空间权限过滤，详情只读；确认及复核请求结果未知时，前端保留原请求并禁止切项目或修改载荷，恢复后再刷新。关键写入使用链路追踪，没有新增常驻后台任务。财务月结属于独立能力，不能以交账完成代替月结。

应收按钮审核独立于工作流审批，内部 `ReceivableReviewService` 支持通过、驳回和反审核。每批1—100笔，携带版本、原因和请求号；历史空审核状态按未审核处理。整批逐空间授权并校验状态后才写入，审核不改变金额。已结、拆分、冻结或占用中的账单不能审核，已支付账单不能反审核；原有金额调整不自动重置审核状态。成功原请求恢复冻结结果并重新检查资产权限，改变载荷或成功日志损坏返回明确冲突，不重复更新或审计。批量账单、逐账日志和请求记录同事务提交，任一步失败全部回滚。按钮及工作台通过下述授权接口接入。

财务月结的内部来源准备器 `MonthClosingPreparation` 按服务端会计账期的实际起止日期核对整期资金，支持跨自然月的期间。它对完整来源逐房屋授权，并对照活动绑定、审核批次和冻结交账明细；关联损坏不能被当作已审核。发生金额、实际现金和未交账/待审核数量由后端汇总，关联缴款或退款的资金流水不重复统计。每期最多一万笔来源，超限明确拒绝；只保留逐笔摘要，避免同时保留整期全部房屋明细。

准备器全程只读，不创建会计账期、不写月结或审计。`allReviewed` 只表示已核对来源均已审核，不能代替可结账判断；内部 `MonthClosingService` 在持久期间门闩内重新核对目录、来源、应收审核及关闭顺序。应收计费账期关闭与财务月结保持独立。

正式月结按会计目录的实际日期顺序执行，账期结束后才可关闭，所有此前已配置账期须已结且与当前期连续；反月结只能从最后一个已结账期开始。项目控制行的 `requireReceivableReview` 历史空值或默认值为不强制审核，启用后要求该期所有有效应收均审核通过；交账无论此配置如何都必须完成并通过审核。预览令牌冻结规则、版本和完整来源，确认时任一变化均要求重新预览。只读预览不初始化账期或控制行。

月结永久保存缴款、退款、资金流水、原存入控制账、交账、应收和票据的来源归属与版本；资金合计区分发生金额与现金，关联流水不重复计数。应收按应收日期、资金按实际发生日期、票据按开具日期归属。每次最多一万条归属记录，超限明确拒绝，不能关闭部分数据。所有来源及成功请求恢复均重新检查原冻结空间权限。不可变资金及票据不因月结被改写金额，原有交账、原存入和应收关闭标记与目录、关闭日期及审计在同一事务发布。

反月结恢复本轮改变的关闭标记及前一期截止日期，保留原月结审计和来源记录；共用交账已经被前一期关闭时不会提前解锁。新开放期间已发生的合法收款、退款、余额消费和红冲全部保留，不以反结回滚资金。成功原请求始终恢复当时结果，换内容复用请求号明确冲突；来源损坏、过期预览、并发版本或末尾审计失败均不留下部分变更。会计目录、月结及规则通过下述HTTP接口开放。自动月结复用同一核对、权限和事务边界。

`FinancialPeriodGate` 提供租户、项目唯一的持久事务门闩，必须由已完成项目授权的业务入口在真实响应式事务中调用。收费库锁序为财务期间、公司及业务来源，锁保持到收费事务结束；基础资料通过独立服务读取，只在提供方本次读取事务内持锁。框架无覆盖 upsert 负责首次并发初始化，不覆盖已结日期。控制行不开放 HTTP 维护或删除。普通收款、退款、预收/押金存入退回划转冲抵、反冲抵、撤销存入、实收转预存、临时收费和预缴确认，以输入的实际资金业务日期校验 `closedThrough`。开放账期仍可缴纳历史已结应收；原成功请求优先恢复原结果并重新检查资产权限，等待期间锁后再次查询成功结果，再校验新操作的日期和来源版本。预缴恢复须重新读取报价，不能重用等待前的状态。

自动结转在锁计划之前取得同一期间锁，包含只减免、不发生余额消费的路径；嵌套调用资金服务沿用本事务锁，不倒置计划、应收和期间的锁序。预览和候选查询不写控制行；失败操作回滚控制行初始化及其业务资金、余额和审计。锁链路使用平台追踪，无新增常驻任务。

独立票据的开具、红冲或作废、重开及收据核销，在公司、来源、额度账和主单锁之前取得期间锁，按本次操作日期校验开放期间。下一开放期间允许办理历史票据，也允许对历史已财务月结应收开具票据；原票和原金额快照保留，红票记录本次操作日期。收据原有的付款关联及已核销不能作废限制继续生效。原成功请求在后续关闭期间仍可恢复，并重新校验资产权限；重开在最外层取得期间锁，嵌套红冲沿用同一事务。

收费设置的新增、编辑、后继版本、批量保存、停止和逻辑删除，以及人工出账，在基础空间、科目、设置或应收锁之前取得同一期间锁。设置的实际生效开始日期和停止结束日期也必须开放，不能在新开放日回填已结配置。自动出账不要求操作员在线：只读加载持久设置并校验当前租户，再取得期间锁，随后锁设置并复核归属；审计使用系统任务身份，不伪造用户登录上下文。新生成应收的实际计费开始日期必须开放，缺失的已结期账单明确拒绝，已逻辑删除、拆分或财务月结的历史身份保持原规则，不重复生成或刷新已结金额。

历史应收导入在全表业务事务开始先取得期间锁，校验本次操作日期和每行计费开始日期；已结行返回Excel物理行号、日期字段及关闭原因，整批不写账单或审计，失败批次独立保留。正式结账使用下述会计目录及月结接口，内部期间门闩不能代替完整核对。

会计账期日历使用独立的 `AccountingCalendarRules`。自然月按各月实际天数；自定义开账日允许1—28日，2—15日的账期标签对应当月至次月开账日前一天，16—28日对应上月至当月开账日前一天，年度首尾分别裁切至1月1日、12月31日。开账日为1时与自然月一致。生成和手工调整均须满足全年十二期标签完整、日期连续、无重叠和空档；此规则只计算日历，不隐式创建账期或执行月结。

内部 `AccountingCalendarService` 显式创建全年目录，按租户、项目和月份保存稳定身份及数据库唯一约束。创建先锁项目期间行，十二期与创建审计同事务保存；同配置重试返回原目录，不同配置、已删除、残缺或日期损坏的年度明确拒绝，不用重新创建掩盖。新年度的开始日期必须开放，已存在的完整相同年度可在月结后继续查询和恢复。年度查询及月份详情不创建目录或期间行，缺失月份返回明确业务响应。

`AccountingCalendarChangeService` 保留会计账期日期编辑能力，提交全年十二期的月份、版本、起止日期及原因；后端先验证年度完整连续，再在同一期间锁中核对全部版本。只变更实际调整的行及其版本，月份身份不变，日期模式标为手工调整，保留原生成开账日供追溯。已结期不能改日期；被移动的日期已有实收、退款、余额流水、票据、交账或应收日期记录时拒绝，不能改变既有事实的账期归属。区间按左闭右开处理，其他日期已有业务不会阻止合法编辑。修改、整年调整前后快照和原因同事务发布，任一版本或审计失败全部回滚。目录不开放通用更新和删除。

### 会计目录、月结与应收按钮审核接口

接口均位于 `/property/finance/projects/{projectId}`，强制当前租户、项目和冻结空间权限，不接受客户端日期覆盖业务日。业务日采用 `property.finance.billing-job.zone` 对应的服务端时区。

| 接口 | 方法 | 资源及动作 |
| --- | --- | --- |
| `/accounting-periods/{year}`、`/accounting-periods/month/{month}` | GET | `property-finance-accounting-periods:query` |
| `/accounting-periods` | POST | `property-finance-accounting-periods:create` |
| `/accounting-periods/{year}` | PUT | `property-finance-accounting-periods:save` |
| `/month-closing/rule` | GET / PUT | `property-finance-month-closing:query / save` |
| `/month-closing/{month}/_close/preview`、`/_close` | POST | `property-finance-month-closing:close` |
| `/month-closing/{month}/_reopen/preview`、`/_reopen` | POST | `property-finance-month-closing:reopen` |
| `/month-closing/{month}/logs/_query` | POST | `property-finance-month-closing:query` |
| `/month-closing/operations/{id}`、`/operations/{id}/members/_query` | GET / POST | `property-finance-month-closing:query` |
| `/receivables/_approve`、`/_reject`、`/_unapprove` | POST | `property-finance-receivable:approve / reject / unapprove` |

月结确认携带 `requestId`、`version`、`token` 和必填原因，先预览再提交。成功原请求可以恢复，即使账期已关闭也不重复执行；修改原请求内容后复用请求号返回409。月结规则携带 `version`、`requireReceivableReview` 和原因，按项目保存，默认不强制应收审核。规则与月结共用期间版本，旧页面不能覆盖已变更规则或关闭边界；不提供修改 `closedThrough` 的入口。

月结历史按原冻结空间读取授权，整期历史列表在分页和计数前完成全部相关空间授权，避免部分可见误认为完整历史；明细只读且分页，内部快照JSON不直接公开。列表查询条件不能扩大租户、项目、月份或操作范围。

应收审核与工作流无关，请求为 `requestId`、`items: [{id, version}]` 和必填原因，每批1—100笔，整批加锁、预检、保存及审计同事务。审核、驳回和反审核由路由固定动作，不能通过请求体切换权限。历史空审核状态按待审核处理；待审核可审核或驳回，已审核或已驳回且未付款可反审核。已结、冻结、拆分归档或被付款、票据等占用的账单遵守原限制。前端按服务端 `allowedOperations` 展示可用操作，详情只读。

## 电子收据编号与打印

电子收据在独立票据模块生成，不消费纸质票据分配池。新编号为 `SJ` + 开具业务时间（17位，含毫秒）+ 请求身份摘要前16位大写十六进制；数据库对全编号设置唯一约束，同一成功请求始终恢复原编号，旧收据号码保持原样。模拟发票仍使用明确的 `SIM-` 编号。

`GET /property/finance/projects/{projectId}/receipts/{id}/print.pdf` 使用独立的 `property-finance-receipts:print` 动作，返回 `application/pdf`、`inline` 和 `Cache-Control: no-store`。调用仍需本项目、租户及整张收据全部冻结房屋的读取权限，不接受发票ID，不发布公开文件链接。前端菜单同步后需给需要打印的角色分配打印按钮权限。

PDF按开具时的公司、购方、客户、房屋、科目、期间及金额快照生成。开具人取首次开具审计，不能被后续作废人的信息覆盖；实时档案变更或来源逻辑删除不改历史打印内容。重印不新增单据、不改变占用、余额及审计。已作废收据仍可查看和打印，各页均标明“已作废”；只有开具时已全部收款的收据显示“今收到 / 实收金额”，先票后款及混合来源使用中性的“收据金额”。

固定A5横向模板及中文常规字重字体随包发布，明细自动分页、重复表头和收据编号，金额大写全程采用精确十进制转换。字体及许可证见 `property-finance-manager/src/main/resources/receipt-templates/fonts`。渲染在 `boundedElastic` 隔离执行，模板不接受客户端HTML、图片或资源地址，所有业务文本转义并禁止引擎访问外部资源；读取快照有1000行上限。损坏快照返回明确冲突，渲染失败返回业务错误，不生成空白的成功文件。入口使用链路追踪，没有新增常驻后台任务或公开缓存。

## 票据分配与票据池

项目接口为 `/property/finance/projects/{projectId}/allocations`，资源 `property-finance-allocation` 分为 `query`、`save`、`delete`、`pool`（维护票据池）动作。支持票本分页、只读详情、多行多本新增、编辑、逻辑删除、号码分页和操作日志；不开放通用物理删除。领用人通过 SaaS 公开用户命令分页选择，保留调用者认证，仅返回有效账号的ID、姓名和用户名。票据类型与来源来自基础字典 `bill_type`、`bill_info_source`，部署时执行同目录 `sql/init-finance-dictionaries.sql`。

新增填写购入日期、领用人、票据类型、代码、来源、可选限额、本数、每本数量、起号、启用/回收及备注。后端计算连续止号，购入日期按填写保存。每行1—99本、每本1—9999张，正整数票号不超过12位，每批最多50行、100万号码，所有行先校验再写入。号码按2000行分片写入，同一租户、项目、类型、代码内不能重号；批内重叠、并发重叠或审计失败均整批回滚，冲突明确返回409。

编辑和删除使用票本行锁及版本校验，存在任一已用号码即拒绝整本编辑或删除。仅修改资料时保留号码独立废弃状态，调整号段时逻辑删除旧号码并建立新池；旧记录及日志保留。删除释放活动号段占用，允许重新分配。单号废弃/启用必须填写原因并使用号码版本，已使用号码不能操作；号码、票本废弃计数和审计同事务更新。票本恢复或启用不会自动启用此前独立废弃的号码。

分配池与电子收据自动编号独立，开具电子收据不扣减此池。查询强制分页，并固定租户、项目及未删除条件，不能由客户端查询条件覆盖。前端详情只读，号码状态操作使用独立确认弹窗，接口错误通过统一消息提示。关键写入有链路追踪，本功能没有新增常驻任务。

## 收据核销登记

`POST /property/finance/projects/{projectId}/receipts/_verify` 使用独立的 `property-finance-receipts:verify`（核销）按钮权限。请求包含 `requestId`、`items: [{id, version}]` 以及可选 `remark`（最多200字），每批1—100张且不可重复。单张、批量使用同一入口；菜单同步后需给操作人员分配核销按钮权限。此处核销是核对收据后的票据登记，不是应收资金核销，不改变票据金额、收款、余额、来源额度及开具快照，也不引入工作流。

只允许核销本项目、本租户下尚未作废、尚未核销且版本一致的收据；发票不能使用此入口。每张收据涉及的全部冻结空间均须具备保存权限。核销保存 `verified`、`verifiedAt`、`verifiedBy`、`verifiedName` 和 `verificationRemark`，历史空 `verified` 按未核销显示。整批按主单ID排序加锁，先检查所有票据再写入登记和各张 `VERIFY` 操作日志；任一版本、权限、状态或审计写入失败均整批回滚。

沿用原系统单向核销约束，不提供反核销；已核销收据不能作废。作废在最终取得主单锁后再次检查核销状态，避免并发产生既核销又作废的票据。成功请求可用原请求号及原载荷恢复结果，仍重新校验当前项目和整批空间权限；更换票号、版本或备注后复用请求号返回冲突，不重复登记日志。

前端在收据台账提供单张及批量核销，确认弹窗展示所选票号、购方和金额，并可填写备注。未知结果冻结原项目、批次、版本和请求号，刷新后从“恢复核销确认”继续查询原操作结果。详情只展示核销信息和操作日志，接口错误通过统一消息提示。窄屏取消表格操作列固定，防止遮挡票据编号。


## 预收与押金原存入票据

独立发票、收据的来源选择支持 `FUND_TOPUP`，`sourceId` 为原始资金流水ID。候选返回 `fundType`（`ADVANCE` 或 `DEPOSIT`），显示原存入房屋、客户、科目、时间及可开金额；收费柜台没有开票入口。仅正向人工收款的 `TOPUP` 可作为来源，退款、划转、冲抵、退回余额、撤销等动作不能冒充原存入。原来源已经消费、部分退款或转出时不再允许新开具，不能用该账户后来补足的余额替换原来源额度。

原存入在确认时冻结客户ID、资金类型和完整标准税快照，预览指纹包含这份资料。后续标准修改、停用、删除或客户结束关联不替换历史名称、税率和商品编码。缺少或损坏历史快照明确拒绝，不读取当前标准猜测补齐；该内部JSON不随普通资金详情或候选接口暴露。新增字段由平台实体建表能力维护。

有效发票和收据共享每笔 `FundCreditEntity.invoiceOccupiedAmount`，同时维护其账户占用；多笔原存入可合并开具，同账户计数按最新版本累计。公司、全部应收和实收之后，资金账户按ID排序锁定，再锁各原存入来源；占用、票据主单、明细和日志同事务。开具不改变余额、现金流水或来源原额，有效占用沿既有资金规则阻止退款、撤销与消费。模拟红冲按原来源释放控制账和账户计数，保留原票历史；任一步失败全部回滚。已付款关联的收据保留不能直接作废的限制。


## 自动月结

项目自动月结默认关闭，与应收计费关期、基础数据同步和自动结转任务独立。接口在 `/property/finance/projects/{projectId}/month-closing` 下：

| 接口 | 行为 |
| --- | --- |
| `GET /schedule` | 查询当前版本、启用状态、执行方式和指定日；无配置返回关闭默认值，不创建目录 |
| `PUT /schedule` | 提交 `version`、`enabled`、`mode`、`day`、`reason`；配置与变更审计同事务 |
| `POST /automatic-runs/_query` | 分页查询本项目的执行摘要：账期、状态、执行人、时间及安全错误码 |

`mode` 为 `MONTH_END` 或 `DAY`。月末模式在实际账期结束后的下月1日执行；指定日为1–28日，取实际期末之后的首个指定日。例如自然1月指定5日为2月5日，自定义1月结束于2月9日则为3月5日。服务端使用 `property.finance.billing-job.zone`，不会在账期最后一天零点提前关闭当天业务。只有已有目录中的最早开放账期可执行，每个项目每轮最多一期；不自动创建年度，也不改写历史实收的账期归属。

配置保存使用月结 `save` 按钮权限及项目 `save` 资产权限，启用时另须 `close` 按钮权限。后台保存并恢复该操作者当时的应用范围、token及维度上限，并与当前真实授权取交集；账户、按钮或资产授权撤销后执行失败，不虚构系统管理员或沿用触发请求上下文。认证快照仅存内部字段，不出现在接口、配置审计或日志。没有匿名执行接口。

配置行锁覆盖整期核对、正式月结、成功任务记录与下次扫描时间；配置编辑与多节点执行互斥。进程中断由数据库回滚，后续扫描重新核对。交账、应收审核、顺序、版本、来源完整性或末尾记录失败时，结账整体回滚；失败另开事务记录，等待1小时后重试。失败记录本身不可保存时，通过安全错误码、告警日志及监控计数暴露，并继续其他项目。人工反结后，本期须重新保存自动月结配置才可再次自动关闭。

后台扫描默认启用，每60秒扫描一次；项目是否自动月结由其独立配置控制。全局可配置：

```yaml
property:
  finance:
    month-closing-job:
      enabled: true
      poll-seconds: 60 # 5–3600秒，和业务失败1小时重试间隔独立
```

运维 MBean `org.jetlinks:type=PropertyManagement,name=MonthClosingJob` 提供运行状态、成功/失败/跳过次数、最后成功/失败时间和安全错误码。保存、执行及扫描复用 `MonoTracer`，不记录授权载荷和个人资料。完整金额及冻结来源仍从既有月结历史按整期原资产范围授权读取，自动记录仅提供不含金额的执行摘要。

## 应收统计

报表只读接口位于 `/property/finance/reports/receivables`，资源权限 `property-finance-report-receivable`：`POST /_query` 使用 `query`，`POST /_export/excel` 和 `POST /_export/pdf` 使用 `export`。打印复用后端生成的 PDF。接口不会刷新计费、初始化账期或修改账务。

请求使用专用 `ReceivableReportInput`，必选 `projectIds`（1–100个）；可按 `spaceIds`、`subjectIds`、`customerName`、`fullName`、`receivableNo`、`receivableDateStart/End`、`dueDateStart/End`、`collectionStatus` 筛选。应收日期与到期日分别筛选，计费起止与计算截至日另行展示；`overdueOnly` 仅返回有逾期欠费的账单。收款状态为 `UNPAID/PARTIAL/PAID`。`groupBy` 选择 `DETAIL/PROJECT/SUBJECT`，`pageIndex` 从0开始，`pageSize` 为1–200。响应包含同一筛选范围的 `summary` 和服务端分页 `page`；汇总不因翻页改变。

沿用旧报表的已审核范围：仅计入 `APPROVED`、未逻辑删除且不是拆分父账的账单。冻结及财务已结的有效账单仍计入。历史客户、房屋、科目名称取账单快照，科目汇总按科目ID及名称快照分组，名称变化不会静默改写历史行。跨项目查询先逐项目验证基础有效性及组织资产读取权限，任一失败即拒绝整笔查询；所有明细、汇总、分组计数与文件在 SQL 聚合前注入空间 `read` 权限，不在分页后过滤或先汇总后屏蔽。项目名称通过基础模块公开命令获取，不访问基础模块内部表。

金额使用已保存的正式财务事实：净应收取 `actualReceivableAmount`，已收取 `paidAmount`，未收逐单按净应收减已收封底零；逾期欠费仅统计到期日早于业务当天的未收，逾期天数对已结清账单返回0。减免为本金减免加实际生效的逾期减免（不超过已计提逾期费用），减免前应收为净应收加减免；不会从净应收再次扣减。收缴率为已收÷净应收×100，保留2位四舍五入，净应收为0时返回0。所有金额和比率通过十进制定点转精确文本返回，浏览器不计算正式金额。

分页、汇总与分组使用数据库查询；单次响应的摘要、总数和记录在同一只读 `REPEATABLE_READ` 事务中依次读取，避免并发收退款造成同一响应相互矛盾。官方 `nativeQuery` 生成含权限与绑定参数的来源 SQL，外层仅使用固定表达式及标准 SQL 聚合和分页；当前持久化行为在 PostgreSQL16 验证，切换其他数据库须验证驱动隔离级别及平台 SQL 映射。代表性项目规模的查询计划、并发和完整网关授权链仍须在部署验收环境验证。

Excel/PDF 导出复用当前筛选及分组，最多10000条明细或分组行，超限明确拒绝，不能截断后当作完整报表。全量数据有界读取，结束数据库事务后在 `boundedElastic` 渲染文件。Excel 金额写数值单元格以便求和，税号、编号和用户文本保留文本以防公式执行；PDF 使用内置授权中文字体、转义文本、禁止外部资源访问并重复跨页表头。查询与导出有 `MonoTracer`，不新增常驻任务或 MBean。

## 实收统计

只读接口 `/property/finance/reports/received` 使用独立资源权限 `property-finance-report-received`，查询为 `POST /_query`（`query`），Excel/PDF 为 `POST /_export/{excel|pdf}`（`export`），打印复用 PDF。项目必选，可跨项目按房屋、客户、科目、收款方式、收款类型、收退款单号、收款员及业务发生日期查询。`groupBy` 支持 `DETAIL/PROJECT/SUBJECT/METHOD/SOURCE/COLLECTOR`，服务端分页、汇总和导出使用同一授权范围。浏览器仅展示金额精确文本，不计算正式资金金额。

实收来源按实际现金流组合：成功收款的人工支付明细为收入，成功 `CASH` 退款明细为负数，预收/押金独立资金流水取 `cashAmount`。原实收不再扣除累计已退款字段；退款按自身业务发生日单列，因此跨期退费不会改写原期收入。`ADVANCE/DEPOSIT` 余额冲抵、`BALANCE` 退款、内部转账与转预存不再次计现。不存在先从应收余额推算实收再扣退款的路径。历史科目、客户、房屋及支付方式名称使用各来源快照；逻辑删除账户仍保留原流水归属。

有收款日期筛选时，发生日位于原费用起止日期内的金额归本期，其余归非本期；非本期包含跨期、未来期间及未提供费用期间的流水，并非仅指历史欠费。无收款日期条件时只返回收入、退款及净额，期间金额为 `null`。资金流水冻结可选的 `calcStartDate/calcEndDate`，撤销原预存继承原期间；缺少结构化期间的旧流水不推测日期。收入、退款为正数，净实收及本期/非本期保留原始现金方向，可为负数。

所有项目先通过基础公开命令及组织 `read` 验证，任何项目无权即整请求拒绝；三个来源均在合并、汇总和分页前注入空间 `read` 权限，只返回可见来源行金额，不泄漏同主单其他房屋的总金额。官方 `nativeQuery` 提供参数绑定和租户存储，随后用同财务域的固定 JOIN、`UNION ALL` 与标准 SQL 聚合；不访问基础模块表、不执行用户 SQL，也不在 Java 内全量聚合。摘要、总数和当前页在同一只读 `REPEATABLE_READ` 快照依次读取。当前数据库为 PostgreSQL16，其他数据库需验证平台映射、CTE、分页与隔离级别，代表性项目规模性能仍在部署验收阶段验证。

文件最多10000条明细或分组行，超限明确拒绝，不静默截断。与应收统计共用 `FinanceReportFile`：Excel 金额写数值以便求和，编号及名称保留文本以防止公式执行，PDF 使用内置中文字体、转义文本和禁止外部资源的重复表头排版。结束数据事务后才在 `boundedElastic` 渲染。查询及导出有 `MonoTracer`，没有新增常驻任务或 MBean。

## 开票统计

只读接口 `/property/finance/reports/invoices` 使用资源权限 `property-finance-report-invoice`：`POST /_query` 为 `query`，`POST /_export/{excel|pdf}` 为 `export`，打印复用后端 PDF。请求 `InvoiceReportInput` 必选项目范围，支持空间、客户、房屋、科目、来源类型及单号、开票覆盖状态、最新发票号码、类型和日期筛选；分组为 `DETAIL/PROJECT/SUBJECT`，分页为0起始、每页1–200条。摘要和分页使用相同的授权及筛选范围。

统计是来源当前开票覆盖，不是期间发票流水或税务申报。每份有效未拆分应收、成功临时收款主单、人工原预收存入各占一行（押金不参与开票统计），避免将应收与其分次实收重复计入；临时混合支付归并主单并扣实际退款，原存入以发生金额为基数，不以当前账户余额替代。历史名称取来源快照，逻辑删除账户不会使原存入历史消失。

已开金额仅统计有效蓝票的 `INVOICE/ACTIVE` 来源占用；共享 `invoiceOccupiedAmount` 包含收据，不能用于该报表。红冲释放原票占用，红票不再次累计，重新开具只统计新有效占用。未开金额逐来源计算基数减已开并封底零，再汇总；它是覆盖差额，仍须由开票流程检查收据占用、时效及资金余额，不能作为立即可开额度。状态为 `UNISSUED/PARTIAL/INVOICED/REVERSED`。日期、号码及类型筛选匹配该来源最新蓝票，已红冲蓝票可作历史展示；同秒票据按创建时间、ID继续排序。

项目逐个校验组织 `read`，来源空间权限在合并、聚合、分页前注入，临时主单要求全部关联房屋可读。若来源参与跨房屋票据而用户无权查看整票，仅返回可见来源自身已开金额，隐藏该票号、购方及票据ID；不能从筛选泄漏受限整票。SQL 使用框架参数绑定、固定 CTE/UNION ALL/窗口排序，不访问基础内部表。摘要、计数、页面在同一只读 `REPEATABLE_READ` 快照依次读取。当前数据库为 PostgreSQL16，其他驱动及代表性项目规模需部署验收验证。

Excel/PDF最多10000条明细或分组行，超限拒绝无截断；沿用 `FinanceReportFile` 的中文、安全文本及精确金额输出。PDF金额列按实际位数分配宽度、禁止金额断行，跨页重复表头。数据库读取结束后在 `boundedElastic` 渲染。查询与导出使用 `MonoTracer`，无新增常驻任务或 MBean。

三类报表导出支持 `exportMode=CURRENT/DETAIL/BOTH`，分别输出当前维度、对应明细或同一工作簿中的汇总与明细，并附查询条件与生成时间。每张工作表上限10000条，超限明确失败。查询与导出各自使用一致只读快照，不承诺跨请求的数据不变。页面筛选（含日期区间）统一进入 ConditionFilter，表格内部滚动并保留底部分页，只读详情仅展示业务字段。

发票台账接口为 `POST /property/finance/reports/invoices/ledger/_query` 和 `/ledger/_export/{excel|pdf}`，沿用开票统计的 `query/export` 权限。台账按整票授权，一票一行，支持项目、空间、科目、购方、开票时间、状态及蓝红类型筛选，关联多来源不放大票面金额。红票为负、蓝票为正，票面税额保留两位、销项税额保留六位，展示差额扣除及征收方式快照；来源覆盖查询与台账是不同统计口径。

## 合同来源与镜像

财务独立保存合同镜像，跨模块只依赖 `property-finance-core` 的 `ApplyFinanceContractsCommand` 及快照 DTO，命令服务为 `financeService:finance-contract`。调用需要 `property-finance-contracts:sync`、项目及整批新旧房屋的 `save` 权限，保留调用者租户，不提供免鉴权入口；其他 manager 不得直接读写镜像表。

合同来源身份 `sourceId` 和同项目合同编码建立后不能改成其他合同，逻辑删除后也不释放编码。增量仅按上游显式删除标记逻辑删除，本次未返回的合同继续保留；同身份可恢复，原创建时间和历史账单不变。全部字段、权限、来源空间和唯一性先校验，再与同步版本、批次审计同事务写入。未变化的已有快照不制造修改时间或提高版本，过期版本和并发冲突返回409，拒绝静默覆盖。首次预期版本为 `null` 或 `-1`，后续使用上次同步结果或 HTTP 适配器在下载前读取的版本。

`POST /property/finance/projects/{projectId}/contracts/_query` 以 `keyword/pageIndex/pageSize` 查询，默认每页12、最多200；`query` 按钮与项目/房屋 `read` 范围在计数和分页前生效。只读 DTO 返回合同编号、名称、来源客户标识/名称、空间位置、履约期间、面积及版本，不返回URL、租户内部字段或原始来源载荷。不开放通用编辑或删除。

`POST /property/finance/projects/{projectId}/contracts/_sync` 接受 `startDate/endDate`（`yyyy-MM-dd`），独立 `sync` 按钮权限。远程地址只配置于 `property.finance.contract-source.url`，默认未配置明确返回503，不伪造已同步。URL应为不含查询串、用户信息及片段的HTTP(S)接口；环境凭据由部署者管理，不能让请求传入URL，不向来源转发登录令牌。GET调用附带项目及日期参数，连接结果20秒超时、响应最多2MiB、每批最多1000条，不静默截断。返回兼容旧 `code=0/data` 数组以及 `id/concatNo/concatName/projectId/houseId/customer/startDate/endDate/leaseArea/isDelete` 字段；任一错误状态、非法结构、编码、字段或项目不符均明确失败，不泄漏上游原始异常体。

下载在数据库事务外，下载前读取本地版本，下载完成后再按该版本原子应用。期间若已有其他更新，整批拒绝409。空间通过基础公开命令校验真实末端，不要求先补计费面积，名称取有权来源快照；历史客户失效不阻止合同历史保留，缺少客户名称时显示上游客户标识。手工同步带 `MonoTracer`，不新设后台调度或 MBean；旧系统已注释的合同定时器不会被无依据自动启用。来源尚未配置时其他计费功能可独立运行。

## 合同账单月度分配

`ContractMonthAllocation` 为冻结合同账单金额提供只读月度分配及六项余额计算。自然月比例与计费共用 `BillingProrationService`：完整月为1，首尾不足月按实际含首尾天数除以该月天数。内部使用28、29、30、31的公倍数表示精确整数权重，避免先舍入月份比例再放大成金额误差；对外 `monthFraction` 仍返回12位小数。

截至月末的分配金额为“账单总额 × 已覆盖月份权重 ÷ 全期权重”，按分截断；末次覆盖月返回完整账单金额，相邻累计相减得到当月金额。例如1000元覆盖完整三个月，依次为333.33、333.33、333.34。单日、31日和二月均使用同一规则，不沿用旧报表固定30天导致的零首段及跨月不一致。它只分配传入的冻结金额，不改写账单，不根据当前标准重算历史费用。

每份账单分别使用截至上月末和本月末的净核销金额，包含余额冲抵、扣除截止日前生效退款；不得从当前累计退款字段倒推历史。期初/期末应收为分配金额超过净核销部分，预收为反向差额；本月应收和净实收分别为两次累计之差，本月净实收允许负数。这里的预收属于合同期间分配差额，不能再次计入独立资金账户余额。应收和预收逐账单封底后合计，不跨账单隐式抵销。六项恒满足“期初应收−期初预收＋本月应收−本月净实收＝期末应收−期末预收”。

### 合同月报查询口径

`ContractReportService` 的只读查询、导出数据和六项下钻共用 `REPEATABLE_READ` 快照及上述分配规则。项目、月份必选，支持合同编号/名称/客户关键词、履约日期、空间及科目筛选。真实来源合同即使没有账单仍显示零金额；指定科目时仅保留具有该科目账单的合同。逻辑删除合同、已删除或已拆分原账不参与当前报表，同项目合同编码关联冻结的 `contractReceivableAmount`，不取开放期间的当前应计金额或重算历史收费标准。

净核销从成功收款主单及核销行，减成功退款主单及退款行，按各自实际业务日期累计到两个截止日；预收、押金冲抵及其退回余额均只计算一次，不另加资金账户或资金流水。孤儿、跨项目或房屋不一致、失败主单、无效日期、超原核销退款等损坏来源明确拒绝，不以过滤坏行生成貌似正确的合计。下钻保留负数净实收，全部非零账单明细相加与对应合同指标一致。

服务直接校验 `property-finance-report-contract:query/export` 及项目读取权限；合同先注入空间读取范围，参与的每套历史账单房屋均再次校验，任一无权则拒绝整份合计。单次参与合同和账单分别最多10000条，超过明确拒绝，分页只作用于最终结果，不截断合计来源；不加载账单内部计算JSON。查询不修改应收、资金或会计目录，链路使用 `MonoTracer`，不增加后台任务。聚合SQL针对当前PostgreSQL环境验证，其他数据库及生产规模的性能需单独验收。

HTTP入口为 `POST /property/finance/reports/contracts/_query`、`POST /property/finance/reports/contracts/{contractId}/{metric}/_details` 和 `POST /property/finance/reports/contracts/_export/{format}`。前两者使用 `query` 权限，文件使用独立 `export` 权限；`format` 仅允许 `excel`、`pdf`。请求使用 `ContractReportInput` 的 `projectId/month/keyword/startDate/endDate/spaceIds/subjectIds/pageIndex/pageSize`，月份为 `yyyy-MM`，履约日期为 `yyyy-MM-dd`；分页默认0、12，最多200。下钻 `metric` 为六项金额的公开字段名，负数净实收仍返回。返回项目名称及精确金额字符串，不提供通用修改或删除入口。

跨模块消费者依赖 `property-finance-core` 中的请求、结果及 `QueryFinanceContractReportCommand`、`QueryFinanceContractReportDetailsCommand`，通过命令服务 `financeService:finance-contract-report` 查询，不能引用 manager 内部服务或表。命令和HTTP共用同一权限与事务入口，不接受后台特权身份。Excel与PDF使用完整筛选范围数据和合计，包含项目名称及统计月份；金额保持文本精度，用户文本不执行公式或HTML，PDF禁止访问外部资源。文件排版在只读数据事务结束后的 `boundedElastic` 上执行，不长时间占用数据库事务。

## 独立基础服务依赖

基础管理继续由 property-base-service 提供，收费服务只打包 property-base-core 公共契约，不打包 base-manager 或兄弟业务。新增房屋、当前客户、项目和字典只读命令适配，不替换现有 directory 命令，不合入旧基础档案业务。启动收费前先启动基础服务并对齐 SaaS RPC/租户上下文。基础读取在提供方自己的事务内完成，收费保存版本快照；两个独立数据库不具备共同事务，基础项目锁不会延续至收费事务结束。

```bash
mvn -pl :property-finance-service -am verify
```

### 收费设置审批

收费设置右上角“审批”打开项目内待审批、已通过、已驳回及全部记录，支持分页查询、只读详情和最多100条批量审批，原因必填。普通新增、批量新增、未出账设置编辑提交后为 `PENDING`，不生成账单；驳回后可编辑重新提交。审批接口为 `POST /property/finance/projects/{projectId}/settings/review/_approve`、`/_reject`，参数 `{items:[{id,version}],reason}`。审批使用 `property-finance-setting:approve/reject` 按钮权限，逐条验证项目和空间资产权限。部署后需重新初始化收费设置菜单并分配新增审批按钮权限。

审批通过后设置为 `APPROVED`，同一事务生成应收，账单 `reviewState` 直接为 `APPROVED` 并保留设置审批人、原因和日期。应收审核状态字段继续展示发布结果；原普通应收审核接口明确返回410，不再修改账单；历史导入、调整及拆分审批保留。源设置待审批或驳回时，手工算费、后台任务及预缴来源均不能绕过。批量中任一项版本、权限、期间或算费失败，整批审批和账单写入回滚。

接续新版本只提交待审批设置，不提前截断旧版本；批准时复核旧版有效性和已出账区间，再切换版本并生成新账。驳回保持旧版不变。新增版本在等待审批期间若原版已出覆盖新生效日期的账单，审批明确冲突，应重新确定生效日期。

已有库在启动新版前停收费服务、备份并执行 `sql/migrate-setting-review.sql`。脚本将存量设置标记为已通过，并将其普通待审核账单承接为审核通过；不改变金额，不发布待审核历史导入，不覆盖已驳回账单。新库由 EasyORM 建表。脚本为 PostgreSQL，可重复执行；非 public schema 请替换后执行。

### 普通账单缴费约束

柜台普通缴费每次仅选择一种支付方式，收清所选每笔账单的当前剩余应收；本次收款金额和支付方式金额只读，不提供部分缴费或混合支付。减免继续通过专门操作提交，后台重新计提并计算减免后核对全额，跨日或账单变化拒绝旧金额并要求刷新。试算和正式入账共用同一规则，不接受直接请求绕过。内部预收/押金余额冲抵仍可部分核销，历史流水不重写，已完成请求的幂等恢复沿用原身份。

## 收费项目范围与新版部署

收费业务统一使用全局项目弹窗。首次进入必须确认项目，即使只有一个项目也不默认选中；普通账务单选，三类报表多选（最多100项目）。左侧仅显示组织，右侧显示所选组织及下级中的授权项目；全选作用于整个筛选范围。项目切换遵守未完成编辑和资金请求恢复守卫。基础管理保持自身上下文，不消费收费的项目选择。报表查询、汇总、分页、下钻及导出均取已确认范围，下钻不能扩大该范围。

已有收费库升级前停收费服务、备份，并在对应schema执行：

1. `scripts/sql/upgrade-finance-refund-applications.sql`：历史来源待退款占额初始化为0，并建立申请、明细和审计表；不改变已成功退款或资金余额。
2. `scripts/sql/upgrade-finance-handover.sql`：交账编号、多附件和费用期间快照字段；历史无法确认的期间保持空。
3. `modules/property-finance/sql/migrate-receivable-business-date.sql`：应收业务日期；仅已确认的历史导入来源回填，其余未知日期不猜测。

启动新版基础服务和收费服务，重新初始化收费模块菜单并重新分配退款审核/修改、交账、票据导出及规则/分配按钮权限。票据二级菜单仅为收据管理、发票管理；规则和票据池/分配从页内入口访问。前端其他模块和基础模块无需复制这些收费页面。

交账统一明细当前有最多10000条的显式读取上限，超限拒绝，不静默截断；尚未承诺大规模性能。模拟发票PDF明确为非税务凭证，所有票据与报表详情只读。
