# 装修管理后端

`property-decoration-manager` 拥有装修申请、配置、附件回执、办理轨迹、巡检验收任务和收退款核验记录；`property-decoration-service` 独立装配。只依赖 `property-base-core` 的公开只读命令读取项目、有效员工和客户房屋关系，不依赖其他系统 manager、不跨业务库查询基础表。

运行前先启动公共基础档案、SaaS 网关和认证基础设施。装修服务默认 HTTP 8505、集群 18505、RPC 28505；数据库 `property_decoration`。部署前核对目标环境端口、网关服务路由、命名空间和应用菜单。环境变量见服务 application.yml；密码、令牌和密钥只写入被忽略的本机配置或目标环境密钥管理。

目录调用会检查目标基础节点支持的具体命令。仅有 RPC 代理、但节点未安装客户房屋等命令时返回 503，不把未接通能力展示成空房屋列表；命令已安装且确无有权数据时仍返回正常空结果。

验收人员资格通过现有 `authService` 的 `GetAuthenticationCommand` 读取候选人的认证，沿用 `decoration.directory.role-server-id` 选择公共认证节点；命令保留指派人的上下文，由提供方检查候选 user 资产读权限。随后仍校验候选人的当前应用任务办理权限；目标项目 read 范围通过基础组织树公开命令，在候选人的认证与应用 Scope 下求值，不在装修库重建组织成员关系。切换仅限该次只读命令，并清除继承的指派人显式 holder；原调用者上下文不变。不使用指派人身份替代、不依赖集群散列选取节点后的故障认证缓存；缺命令明确 503，拒绝或无有效候选仍拒绝指派。

检查配置Excel格式沿用原PC的19列：验收场景、所属项目、房屋类型、装修类型、检查大类及排序、检查小项、填报类型、必填/启用、小项排序、文本/数值/图片标准、上下限、选项、默认标准项和示例图片。项目名必须唯一映射到当前有权项目；房屋类型的编码或文案必须唯一映射到公共启用字典，不能从上传文件或浏览器声明主数据。公共字典只读契约为 `QueryPropertyDictionaryItemsCommand` / `propertyService:dictionary`，由基础档案持有，沿用公共字典的认证读取规则，仅返回启用分类的启用项；缺少命令时消费方503，不猜测编码。

导入按项目、房屋类型、装修类型、场景分组，同分类同名小项合并并保留ID，未出现项保留。`CheckItem.categorySort` 表示分类排序，`sort` 表示分类内排序；已有未设置分类排序的配置沿用整体排序。文件解析与合并计划不执行写入或上传，任一行无效时不产生可执行分组。模板和数据都使用同一19列；物理行号用于错误定位。支持xlsx浮动图片及WPS DISPIMG图片，仅解析本工作簿内资源，不执行普通公式或读取外部图片。最大10MB/1000个数据行/64MB展开内容；每行最多一张JPG或PNG、2MB。POI解析由编排层调度到boundedElastic。

检查导入端点为 `GET /decoration/configurations/checks/import-template`、`POST /decoration/configurations/checks/import?requestId=...`（multipart `file`）和只读 `GET /decoration/configurations/checks/import-result/{requestId}`，均使用配置保存权限并要求有效员工。请求号最多64字符，按应用、租户和操作者隔离；同键不同文件拒绝。先捕获所有现有配置版本、完成整批合并预检，再上传私有模板图片，配置与 `pd_configuration_import` 成功收据同事务保存。版本冲突或任一保存失败整批回滚，已知临时图片在事务结束后补偿删除；不能确认外部上传结果时不自动重试。外部上传/写库开始后的有限操作不随浏览器断线取消，客户端可凭原请求号查询结果。同请求竞争先回滚失败事务，再核对赢家收据，防止重复增加配置版本。结果读取重验当前项目权限，不重新执行导入。成功收据不保留原始工作簿。

```sh
mvn -pl :property-decoration-service -am verify
```

使用 Java 17，行为测试通过 Testcontainers 创建隔离 PostgreSQL，不读写业务库。发布产物为 `services/property-decoration-service/target/application.jar`，只包含本系统 manager 和公共 core；本地 application-local.yml 不打入产物。

业务接口仅提供受控动作，不开放通用实体保存或物理删除。项目范围来自基础组织树命令的 AssetsHolder 授权结果，只接受显式标注为项目的节点；平台直属应用允许无技术租户，仍须具备平台激活的应用 Scope。`decoration.directory.server-id` 可将基础命令固定到指定公共节点（默认使用集群选择）；装修 SQL 再固定可信应用与租户边界。分页、详情、附件、统计、导出及动作使用同一边界。创建通过唯一房屋占用与稳定请求键防并发；动作通过聚合行锁、版本与轨迹原子提交。超时核对端点只读查询；同键不同内容拒绝。

附件内容通过 SDK 已有 `fileService` 流式上传、下载和删除命令访问公共文件服务；`decoration.files.server-id` 必须明确配置公共节点。未配置、节点不可用或命令缺失时拒绝操作，不退回本机文件存储。装修库仅保存私有业务回执和公共文件 ID，浏览器读取仍经过装修项目、应用和租户范围校验，不暴露通用文件访问地址。上传或补偿删除均不自动重试，避免未知结果时重复写入。

独立服务关闭原始 `file.manager.upload-filter` 自动注册，改为装饰同一公共过滤器：保留公共后缀策略，并恢复其 multipart 请求重建后请求头的大小写无关读取。此适配不从客户端推断租户，也不替代平台租户检测和认证。

验收申请使用 `AcceptanceRequest`，必须提供申请验收日期；提交时间、申请人和来源由聚合事务从可信上下文生成。人员指派仅使用 `Acceptance`，不得修改已提交的日期或申请人。任务保留创建时的装修和本轮验收申请快照，后续轮次不覆盖历史；旧任务未记录字段返回空值，不根据任务创建时间推算申请日期。

整改任务的 `feedback` 仅表示原巡查意见。提交整改、整改复核、重指派及重发分别在 `details.handlingRecords` 追加办理人、时间、处理后状态、意见与当时复核角色；提交整改另存当次附件。快照与任务状态在申请聚合事务中提交，幂等重试不重复记录，后续整改不得覆盖此前附件或意见。重发创建新任务并保留原巡查内容，通过 `sourceTaskId` 关联原记录。沿用聚合动作和HTTP/SQL追踪，无新增常驻状态或MBean。

`DecorationFinanceGateway` 与 `DecorationNotificationGateway` 是真实集成边界。无提供方时，资金办理和通知发送返回503；不能在客户端或数据库中手工制造支付成功以绕过发证门槛。财务核验校验资金方向、单据类型、金额、归属与唯一回执。二验后一次性退款结算成功才自动结束，手动结束与退款是不同动作。外部调用必须支持契约中的稳定幂等键。

退款仅在二次验收通过后一次性结算。金额取申请冻结协议的 `refundAmount`，未配置时退还实收保证金；配置不得为负、超过保证金或超过两位小数。旧协议的 `firstRefund`、`secondRefund` 只合并为总额，不再开放首验退款；历史已核验退款从总额扣除，不能重复退。零金额仍需显式结算，不伪造外部交易回执。退款成功才释放房屋占用并自动结束，PC/H5使用同一资格规则。

本机联调可显式设置 `decoration.integrations.simulated.enabled=true`（环境变量 `DECORATION_INTEGRATIONS_SIMULATED_ENABLED=true`）启用模拟支付、退款及消息提供方，默认关闭。PC/H5 显示“模拟缴费”“模拟退款”按钮，调用管理端或本人端 `/{id}/simulation/payment`、`/{id}/simulation/refund`，由服务端生成模拟单据。独立测试接口仅接受模拟提供方，关闭模拟或配置真实提供方时返回503；复用原缴费/退款动作权限、本人关系、状态机、金额核验及动作幂等，不要求测试者手工编造财务单号。真实线下核验接口仍要求物业员工及真实单据。模拟回执持久化于装修库的 `pd_simulation_receipt`，同请求重试返回原结果，同键不同内容拒绝。回执提供方标记为 `SIMULATED_DECORATION`，能力接口返回 `simulated=true`，PC/H5 详情展示模拟提示；不产生真实资金交易或消息发送。该配置仅用于明确授权的测试实例，不代表真实财务接入完成。

同一模拟开关也启用 `SimulatedDecorationChargeItemGateway`，为原收费科目选择接口提供“装修保证金（模拟）”和“装修服务费（模拟）”，支持名称包含搜索及分页，不创建或修改收费主档。正式收费目录提供方存在时优先使用正式提供方；关闭模拟开关且没有正式提供方时，仍明确返回503。项目、员工及应用权限继续由原目录入口校验，不提供假角色或绕过授权。

备案状态独立于装修流程状态：新证未登记领取为待领取；领取后先判断有效期，再判断延期快照，否则为已领取。已发布的旧数据仅有打印时间时保留原流程资格，但不补造领取人、领取时间或图片。`permit` 列支持框架 `json_value` 查询打印时间，以及 `decoration-permit-state` 条件（`pending`、`issued`、`extended`、`expired`，值可多选，`$not`取反）。状态以服务端查询时刻计算，条件在现有权限边界内执行后分页，不加载全量记录。此映射复用独立服务已限定的 PostgreSQL 框架JSON支持，不修改现存文本快照类型；其他数据库需提供对应JSON映射。查询沿用框架HTTP/SQL观测，无常驻状态，不新增手动追踪或MBean。

备案证件通过 `GET /decoration/applications/{id}/permit/document` 只读准备，要求打印权限、有效员工、统一申请范围及已审核收款；响应 `Cache-Control: private, no-store`。`DecorationProjectSealGateway` 为项目章只读集成边界，实现必须保留认证/资产/租户上下文，经公共档案及文件公开能力获取章，不接受客户端URL或装修附件替代。缺提供方503、项目未配章409；校验应用/租户/项目归属、PNG/JPEG真实解码、2MB和4096×4096上限，图片与摘要运算在boundedElastic。首次准备返回申请快照、私有data URL和SHA-256摘要；当前有效期已有打印图片时返回原私有附件回执，不再读取最新项目章。不在装修复制印章主档，不臆造公共命令或默认章。

PC先生成完整带章PNG，通过装修私有附件 `purpose=permit` 上传（打印权限、有效员工、本申请范围、20MB、真实PNG解码及4096×4096限制），再以原版本、稳定请求号、`PrintPermit.sealDigest` 和 `snapshotFileId` 调用 `/{id}/permit/print`。聚合事务校验章摘要及专用附件归属；缺章、换章、无效图片及未付款不留下打印登记。每次打印追加图片回执、有效期、操作人和时间，详情展示原图；重复打印和历史下载复用已冻结的原图，不重新套用新章或新模板。独立证件保留原施工时段、13项须知及版式，业主姓名、联系电话沿用申请冻结信息，不另设备案人字段。未知结果先只读核对原请求，成功后输出同一图片；设备失败可重试输出而不再次登记。登记只证明发起打印，不能证明纸张输出或领取，浏览器取消打印不回滚登记。

`POST /decoration/applications/{id}/permit/collect` 沿用打印动作权限及员工、申请资产范围、版本和幂等边界，要求已有当前有效期的图片，记录实际领取人（可代领）、实际领取时间、当前登记操作人及对应图片回执；禁止重复领取，实际时间不能早于该版首次打印或晚于当前时间。新申请登记领取后才开放验收申请。每次领取追加不可覆盖的历史记录。

领取后延期追加原有延期记录，保留旧版图片、打印及领取记录，清除当前打印/领取摘要并进入待领证状态；新有效期必须重新生成、打印和登记领取。未保留图片的旧打印时间在延期时转存 `legacyPrintTime`，不伪造历史图片或操作人。现有聚合/HTTP/SQL追踪覆盖这些动作，临时图片有限生命周期，无新增常驻任务或MBean。

PC/H5 源码和业务对照文档位于相邻装修管理前端仓库。此目录不包含生产凭据或自动部署指令。

装前自检使用独立 `pd_self_inspection` 记录。与旧系统一致，业主申请创建时在同一事务生成一份自检快照，PC 不单独新增；请求重试不重复生成。PC `/decoration/self-inspections` 提供分页、详情和带版本的逻辑删除，沿用 `decoration-application` 的查询/删除权限及统一项目、应用、租户范围。删除仅隐藏自检记录，不改装修申请、办理轨迹或附件归属；附件回执仍绑定原申请，不用自检 ID 冒充装修 ID。现有申请历史不自动回填为自检记录。验证覆盖业主创建/重试/回滚、PC 不生成、跨范围拒绝、分页筛选、删除后快照与附件保留。新增接口沿用框架HTTP/SQL观测，创建沿用聚合追踪；无常驻状态，不新增MBean。

概况统计按旧首页口径返回汇总、审批流程分布和房屋类型分布。累计户数按房屋去重；在装/完工按同项目同房屋最新申请的退款状态划分，手动结束不能替代退款成功。环比比较上海时区本月与上月完整自然月：申请户数按提交时间，完工按退款时间，收款按核验时间；上月为0时本月非0为100%，均0为0%。`_statistics` 在未发布实现中统一为此报告结构，不保留中间状态计数格式。使用QueryHelper对静态聚合SQL注入统一授权QueryParam，数据库聚合，不加载申请全集；JSON材料筛选沿用服务已有PostgreSQL范围。最新申请关联有复合索引。验证需覆盖重复房屋/时间并列、跨月、分项审核、空结果、OR越权及代表性规模；真实数据为空时只验接口接线。沿用HTTP/SQL观测，无新后台状态或MBean。

管理端记录修改区分计划竣工与实际结束：`/{id}/completion-time` 仅修改未结束申请的计划日期；`/{id}/actual-end-time` 在 `save` 权限下登记或纠正实际结束时间，要求不早于申请开始。登记实际结束将申请置为已结束并释放同房占用；已结束记录可纠正日期，不支持清空重新激活，不改结束原因、计划日期和财务状态/单据。后者复用统一范围、有效员工、事务、版本、幂等及历史快照。PC详情在结束后保留时间纠正入口，业主接口不开放该动作。记录页“是否生效中”沿用旧许可区间开区间口径，与装修是否结束独立；备案页不再把发证员工当作业主或备案申报人展示，姓名和电话统一沿用申请快照；历史员工电话字段保留只读兼容。

日常巡检通过公开`authService:role`命令读取当前应用可见的启用角色；`decoration.directory.role-server-id`可明确指定节点。缺命令返回503，合法空目录正常返回空页。模板应允许role资产的business_application选择策略，应用绑定可用角色，办理角色配置同策略。候选读取不代替本人执行资格，复核角色名称由服务端验证后冻结，重指派同样校验目录。

巡检计划冻结各角色的间隔天数（1～1000）、有效时段、检查项、整改复核角色及指派人。按上海自然日与计划起始日的间隔计算，当天到期角色共享一项日期任务；各角色周期分别生效，前期未完成不阻断后期。一项任务仅反馈一次，办理者须为当前有效员工、有目标项目和handle权限且当前认证角色匹配。重新指派不覆盖当天已生成的快照。PC巡查页先列已发证装修申请供指派，日期任务位于独立页签。

计划与索引游标位于申请聚合，后台响应式每分钟处理最多100份计划、每份最多追赶30个自然日。首次指派不补造过去任务，停机恢复按持久化游标补齐；结束/删除停止生成。后台与人工动作共用申请行锁，日期任务使用申请+日期的确定性ID，多实例/重试不重复；游标更新不增加人工动作版本，失败整份事务回滚。decoration.inspection.scheduler.enabled可关闭调度，delay和initial-delay设置毫秒间隔。批级追踪/property/decoration/inspection-generate复用平台SQL观测；JMX org.jetlinks:type=DecorationInspection,name=Generator提供累计生成、失败和最近成功时间，无业务修改入口或隐私字段。

员工H5通过 `POST /decoration/tasks/mine/_query` 查询个人任务：验收按可信本人指派，待巡检按当前认证角色，待整改复核按冻结复核角色，历史按实际执行人或办理记录中的操作者。统一应用、租户和有权项目条件与个人条件以AND组合，JSON角色/办理快照在PostgreSQL中筛选后分页；不接受浏览器指定操作者。接口要求有效员工及任务查询权限，办理仍分别检查handle/review权限和任务本人/角色资格。

巡检不通过在同一聚合事务生成 `owner_rectification` 记录，业主可直接读取并提交整改，不再经过整改通知审批；巡检计划只要求巡检角色与整改复核角色。业主提交后进入 `waiting_review`，通过/驳回及办理历史仍按既有角色复核规则执行。外部通知仍需提供方真实受理，不以直接下发业务任务伪装推送成功。既有历史快照中的通知审核字段只作历史信息保留，不再产生新审核动作。
